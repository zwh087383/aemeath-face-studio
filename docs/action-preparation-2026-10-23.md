## 3. 准备册和审阅队列怎样使用

本机入口是[动作准备册](http://127.0.0.1:18794/action-preparation/)。它可以按类型、状态、用途或缺口查找，显示每条记录与证据。原生条目可打开当前 PMX 与原骨架对照；这证明可以检查素材，不代表已经接好了动态进入、退出和真实语音。

资料页也可把已有原创手势、表情、头眼反应、活动和连续配方交给各自的原有播放器，并核对实际接纳的动作身份。统一的是查找和打开入口，不是已经将这些播放器合并成正式人物控制器。没有可测轨迹的归档条目不提供误导性的播放按钮。

本机[逐组审阅队列](../outputs/action-preparation-20261023/review-queue.md)把全部 828 条记录分为 **284 个审阅组**，机器可读版本是[review-queue.json](../outputs/action-preparation-20261023/review-queue.json)。原生身体按 149 个来源组安排；56 手势、65 活动和 7 配方分别保留；其余配套层单列。

顺序先看常用站姿交流，再看事件反应、坐姿与起坐、转向和位移、持物与桌面、多人接触、连续活动及特殊演出。同用途优先检查原生，再比较已有原创究竟补了什么控制能力；不能因为“原生优先”就把含义未知的动作直接塞进日常交流。

每组会告诉审阅者：为什么现在看、需要什么场景、先看哪段入口和出口、三种取消点如何复核，以及失败后先补什么。接缝分层把姿态差与速度差分开；源端点接近的组仍须看实际衔接。按本轮排序，50 个来源组的源端点较接近，23 个主要需复核速度差，1 个需重点复核姿态差；缺阶段和单段式另列。

例如坐着说话的一组，要先放好对应座椅，确认当前确实坐稳，然后完整看 Start、Loop、End；再从准备、主动作和收回分别取消。观察手有没有突然反向、脚有没有滑、身体是否保留座面承接、衣发是否脱节。找不到可靠出口，就留下具体缺口，而不是把“自动调用”打勾。

## 4. 怎样防止源动作换了，旧测量还被当作有效

每次构建总目录会核对资源清单、已测原生片段、表情文件、目标 PMX 及参与测量的程序依赖的指纹。这里的指纹就是文件内容的核对值：同一个路径的内容变了，也应要求重测，不能只凭文件名一样继续使用旧结果。

原创测量会追踪实际本地导入依赖，包含手臂求解、骨架与连续过渡等相关程序。总目录再校验测量输入，不接受来源不符的旧资料。审阅队列同时记录总目录与用途规则的核对值，保留原始 ID；换来源后必须重建相关测量和队列。

发现变化时，停止合并这一份旧证据；原始资源与现有正式语音流程不因此停用。重新测量并验证的是受影响版本，不能自动继承此前观感或打断通过记录。

## 7. 前期准备还缺什么，怎样继续

| 接下来要做的事 | 怎样实际做，谁确认 | 缺少时怎样处理 |
| --- | --- | --- |
| 逐组确认真实用途并排除攻击 | 制作人员按队列连续看原生及近似原创，登记真实作用、幅度和所需对象 | 保留未知用途，不靠模型评价或文件名放行 |
| 原生的动态进入和退出 | 从当前显示姿态与速度接入，补可停阶段、落脚和收手；在模型上看，不只比较两个文件的端点 | 没有可执行出口的版本继续只预览；不能写一句“平滑过渡”就算准备完成 |
| 完成 7 条连续活动 | 实际串起子动作，保留世界位置、朝向、支撑和物品，逐接缝检查，再从各阶段打断 | 子动作各自通过也不等于整条配方通过；物品省略不能当作放下 |
| 固定尺寸持物与可靠放书 | 先固定书的尺寸和双手握点，准备可达桌面；书到达承接位置并稳定后才能松手 | 当前仍按手距缩放的显示不支持可靠交接；合书仍持书，不是假定已放下 |
| 衣发与表情的实际组合 | 身体与衣发同进度，核对近身肘部和袖口；眉眼、口型与眨眼统一分工，取消后恢复数学情绪底色 | 有冲突的组合不启用，声音仍按既有流程播放 |
| 给具体可用版本留下证据 | 记录当前模型、动作、入口、场景、退出与取消结果；制作人员连续观看，程序记录实际输出 | 不把固定空手站姿结果扩大成坐姿持书，也不把截图当动画观感通过 |

这几项属于前期准备，能够在本地独立完成，不必先接云端对话。正式数学状态桥、统一人物调度、完整双工语音、记忆和历史保护的全链路验证属于后续接入工作；本批没有把它们改成另一套简化流程，也没有新增云端调用。

第一批可执行组合可以先用空手站姿完成待机、倾听、交流手势、三阶段打断和收稳；随后扩大坐姿、起坐、转身、持物和连续活动。全库资料继续保留，未验内容也继续推进，不把暂时能演示的一小组重新定义成整个目标已经完成。

## 8. 本机重新生成、测试与打开的方法

以下 PowerShell 命令从项目根目录执行，使用本机已有 Node、Python/NumPy 及 `preview/node_modules` 依赖。源游戏导出与 PMX 留在本机；仅克隆公开工具而没有这些文件时，不能生成真实资料。

先进入工作目录，再按顺序生成三类测量、总目录和审阅队列：

```powershell
Set-Location -LiteralPath 'F:\AI-Shared\model_test\face'
python .\scripts\action-preparation\prepare_native.py
node .\scripts\action-preparation\prepare-authored.mjs
node .\scripts\action-preparation\prepare-expressions.mjs
node .\scripts\action-preparation\build-catalog.mjs
node .\scripts\action-preparation\build-review-queue.mjs
```

默认输出是本机 `outputs/action-preparation-20261023/`。要把队列写到另一份审阅目录，可运行下面一条；它读取现有总目录和规则，只写指定目录下的两份队列文件：

```powershell
node .\scripts\action-preparation\build-review-queue.mjs --output-dir '.\outputs\action-preparation-20261023\review-copy'
```

专项测试与真实模型离线检查分别执行：

```powershell
python -m pytest -q .\tests\test_action_preparation_native.py
$preparationTests = @(
    '.\tests\action-preparation-authored.test.mjs'
    '.\tests\action-preparation-expressions.test.mjs'
    '.\tests\action-preparation-catalog.test.mjs'
    '.\tests\action-preparation-fingerprints.test.mjs'
    '.\tests\action-preparation-review-queue.test.mjs'
    '.\tests\action-preparation-server.test.mjs'
)
node --test @preparationTests
node .\scripts\action-preparation\validate-target.mjs
```

最后一条会全帧重测目标骨架，并按报告说明抽样实际蒙皮，不代表 GPU 或连续观感。需要长时间计算时先看已有报告是否与当前资源一致，不为了修改文档重复跑整库。

启动独立准备册并打开页面：

```powershell
node .\realtime\action-preparation\server.mjs --port 18794
```

保持该终端运行，在另一个 PowerShell 窗口打开：

```powershell
Start-Process 'http://127.0.0.1:18794/action-preparation/'
```

如果 18794 已在运行，直接打开已有页面，不另起重复服务。若端口被其它程序占用，先查明归属，不自动终止其它服务。原生对照入口为同端口的 `/native-resources/`。

浏览器复核使用本机已有 `playwright-cli`。`scripts/action-preparation/browser-review.cjs` 核对准备册；`browser-target.cjs` 在已加载的 `/native-resources/` 页面检查全部身体，并返回报告。两者都是交给 `playwright-cli run-code --filename=...` 的页面脚本，不能直接用 `node` 启动。浏览器结果输出与截图应保存到本机 `outputs`；目标检查包括首次加载等待，不能把脚本结束时间当运行帧率。
