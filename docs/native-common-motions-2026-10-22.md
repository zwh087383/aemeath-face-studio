# 爱弥斯常用原生动作库（实验性）

用户验收单段 Stand2 后，继续提取适合日常交流的非攻击动作。本批提供 **73 个片段、33 组动作用途**，共 6693 帧、约 220.67 秒原始动画；71 段来自爱弥斯本人的剧情 Body 动画，2 段为女性中体型共用前进/后退步行。所有动画数据、网格、贴图、资源索引密钥和录制证据均留在本机。

## 内容

| 分类 | 片段数 | 主要内容 |
| --- | ---: | --- |
| 待机 | 3 | 自然站立、呼吸、放松 |
| 交流 | 21 | 两组说话、平静交流、转折/展手说明、低声说话、指向 |
| 思考 | 7 | 两组思考，其中一组带两段循环 |
| 情绪 | 15 | 生气、尴尬、害羞、抱怨、别扭反应等身体姿态 |
| 小动作 | 12 | 招呼、拨发、面颊手势、响指、抱臂笑等 |
| 转身 | 2 | 左转/右转 90 度 |
| 坐姿 | 9 | 基础坐姿、坐着说话、坐着思考 |
| 行走 | 4 | 行走说话、行走思考、共用前进/后退 |

名字按原始资源命名标注，不把文件名当作已经确定的剧情语义。数量中的“片段”包括起势、循环与收势；33 组是按动作基础名称去掉阶段后缀整理的用途，不把 73 段称为 73 套独立完整动作。

首选资源前缀为 `Client/Content/Aki/Sequence/SequenceAnim/DialogAnim/FemaleM/Aimisi/Body/`。这比只检索角色 CommonAnim 目录能找到更多日常剧情动作。共用步行为 `Client/Content/Aki/Character/Role/FemaleM/BaseAnim/Walk_F.uasset` 和 `Walk_B.uasset`。

白名单排除了攻击、技能、爆发、处决、闪避、受击、死亡、武器展示；未把 Montage、BlendSpace 或 RibbonAnim 伴随衣带动画当作主体片段。纸飞机、海豹、变形剑等明确依赖道具的角色待机未纳入本批。握手、牵手、拥抱等需另一人物的动作也未纳入。

## 预览

运行 `node realtime/native-library/server.mjs --port 18790`，打开 `http://127.0.0.1:18790/native-library/`。

- 原生灰模和当前 PMX 同步比较，可以按类别筛选、搜索、暂停、拖动、切视角、调速度和顺序观看。
- 每次只读取选中的片段，内存中最多保留 3 份原始片段 JSON；服务器为较大的 JSON 按需 gzip，缓存最多 4 份压缩数据。
- 每次切换先恢复两套模型的绑定姿态，再建立新适配器，避免动作之间积累变形。旧网络请求不能覆盖后选动作；加载失败会保留原画面。
- 单次片段到末尾停止，循环片段按清单循环。“顺序观看”是素材审阅，不是已经接好的自然表演编排。
- 默认跟随人物。Salut01 有显著原生位置变化，相机跟随保留源动作的世界位移；可关闭跟随观察实际移动。坐姿会调整观察焦点。
- 左侧为原生动画数据在原生网格上的灰模重放，右侧为现有 PMX 的重定向。没有恢复完整游戏材质、表情图层、衣发物理或场景。

## 适配与验证

继续使用上一批的坐标转换、绑定姿态校准和保骨长重定向，没有更改原有手写动作库、近身肘部、利落挥手、语音或打断系统。

- 白名单 73 项全部在本机索引精确存在，73/73 解码成功，全部为支持的非 additive UAnimSequence。
- 71 段专属片段使用 `R2T1AimisiMd10011_Skeleton`，388 源骨骼，对应 192 个目标骨骼；2 段共用步行使用 `R2T1PlayerFemaleMd10011_Skeleton`，197 源骨骼，对应 83 个目标骨骼。
- 全 6693 帧进行了离线骨架适配检查，无非有限值、无骨长变化。7 个重点关节的最大位置差约 0.22661 PMX 单位，按源尺度约 1.75 cm；这不是衣服碰撞误差或完整表面相似度。
- 原有单段/坐标数学测试和新库 HTTP 边界测试共 8 项通过，覆盖白名单别名、未列出资源、遍历、写入、Host、gzip 内容一致性等。
- 真实 Chrome 对 73 段各取 5 个时间点，共 365 组采样；所有片段的源/目标蒙皮采样都有变化，骨长稳定。逐段暂停、恢复、循环或单次结束行为通过，无浏览器异常。
- 初次页面只请求 1 段；延迟 A 请求、先完成 B 后，A 不会覆盖 B；A→B→A 恢复同一时间的姿态一致；搜索、类别与四视角检查通过。
- 跟随相机改动后另做视觉专项：Salut01 取 9 个时间点，两侧焦点位移跨度约 108.87 / 108.34 场景单位；开关跟随不改变骨骼世界位置，关闭后焦点固定。坐姿头、髋、双手、双脚都在画框内；已保存并查看坐姿与致意等截图。
- 单段解码工具重构后重新导出的已验收 Stand2，与上批动画 JSON 的 SHA256 完全一致：`9eb819beaef621f60b9177bb759c33ce07a9984f4f3487e12597f01de52f04f5`。

27 个循环候选中，20 个超过极严格的原始全骨局部变换闭合阈值（位置 0.02 cm、旋转 0.002 rad、缩放 0.002）。其中最大的原始旋转首尾差约 0.0583 rad（3.34 度，行走思考片段）。原始曲线已保留，并写入清单验收元数据；后续自然调度应做过渡，不能宣称所有原始片段都可无缝硬循环。

坐姿依赖座椅与锚点，当前为空场姿态预览。四段步行是原地身体曲线，游戏场景中的角色平移需要运行时另行驱动。拨发的一组只有起势和循环，未编造原本不存在的收势。情绪分类表示身体姿态，面部表情仍需通过现有表情层另行协调。

本次首屏双模型准备在并行机器负载下测得约 61.5 秒，仅为一次加载样本，不作为稳态播放性能结论。本批没有调用云端模型。

## 文件与复现

- `scripts/native-motion/common-candidates.json`：可审查的 73 项白名单，只含资源路径和分类等元数据。
- `scripts/native-motion/Program.cs`：新增 `export-list`，同一次挂载处理明确清单，限制条数和片段长度，拒绝战斗路径和 additive。
- `scripts/native-motion/run-common.ps1`：带显式本机 PAK/补丁/密钥/工具路径参数的导出入口，拒绝覆盖已有清单。
- `scripts/native-motion/audit-library.mjs`：全帧离线适配检查；`finalize-library.mjs` 生成包含动作组、来源、阶段和验收信息的清单。
- `realtime/native-library/`：按需读取的对照播放器与仅回环只读服务器。
- `tests/native-library.test.mjs`、`scripts/native-motion/browser-library-acceptance.cjs`：无需游戏素材的服务边界测试，以及使用本地素材的真实浏览器验收。

本机证据目录为 `outputs/native-common-motions-20261022/`：包含原始导出、validated/exported 清单、离线检查、浏览器报告、截图和源码/资源指纹。该目录不随 Git 上传；源网格复用上批 `outputs/native-motion-20261022/` 的配套灰模。

```powershell
node --expose-gc scripts/native-motion/audit-library.mjs
node scripts/native-motion/finalize-library.mjs
node realtime/native-library/server.mjs --port 18790
node --test tests/native-motion.test.mjs tests/native-library.test.mjs
node scripts/native-motion/browser-library-acceptance.cjs
```

解码工具仍依赖上批在本机独立目录构建的 CUE4Parse / ACL native，参见单段实验说明。更换白名单后需要新输出目录并重新执行验证；成功解码不等于所有场景接触、衣发效果和自然衔接都已验收。
