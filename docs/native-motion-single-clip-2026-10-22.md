# 爱弥斯单段原生待机：本地提取与 PMX 适配实验

本轮验证鸣潮现有原生动作能否替代继续手写关节轨迹：从本机客户端读取一个最终选用的待机片段，在原生游戏骨架和现有 PMX 模型上同步重放。没有批量扩充动作库，没有替换语音、调度或原有挥手动作。

## 片段与比较口径

- 最终片段：`Client/Content/Aki/Character/Role/FemaleM/Aimisi/CommonAnim/Stand2.uasset`。
- 长度：4 秒，121 帧，388 个源骨骼；ACL 压缩动画，非 additive。
- 配套原生骨架/网格：`R2T1AimisiMd10011`。现有目标模型：`鸣潮_爱弥斯1.05.pmx`。
- 读取基础包并叠加本机 `3.7.13` 资源补丁，挂载 102 包，索引 2,024,828 条文件路径。索引扫描不等于批量导出素材。
- 为判断第一个候选的姿态，实际解码了两个候选：`XA_Loop_Stand` 和 `Stand2`。前者全身方向不适用于本轮普通站立验证，保留在私有诊断输出；只有后者进入页面。没有据此推断前者损坏。
- 左侧是**原生网格、原生骨架及原生动画数据的灰模重放**，不是游戏录屏。右侧为现有 PMX 的适配结果。两侧共用一个时间变量，支持暂停、拖动、0.25/0.5/1 倍播放和四个观察方向。
- 灰模未恢复游戏材质、灯光、独立脸部表情图层及运行时布料。此实验不能证明最终游戏画面逐像素一致，也不代表已还原全部衣发效果。

## 适配实现

1. CUE4Parse 负责资源索引、当前游戏格式与 ACL 轨迹解码；只导出指定动画和一个必要配套网格。`LoadVirtualPaths()` 用于正确解析 ACLPlugin 压缩设置。
2. 统一坐标转换使用 CUE4Parse glTF 导出器同样的 `(X,Y,Z) → (X,Z,Y)` 及四元数转换，源动画单位仍是厘米。使用骨长比例估计目标比例。
3. PMX 的初始手臂角度、手掌和手指姿势与游戏绑定姿态不同。适配使用源骨骼世界旋转相对绑定旋转的变化，再乘目标姿态校准；不会直接复制局部欧拉角。
4. 保留 PMX 骨长，驱动腰部整体位移，以及躯干、头、四肢、手指、D 腿辅助链和可同名匹配的衣发骨。总映射 192 骨；这不等于全部 388 源骨都存在目标对应物。
5. 不启用 MMD grant、IK 和额外物理，避免第二套求解器覆盖同一段原生曲线。目标世界矩阵按父到子单遍更新；暂停后停止无意义重绘。
6. 原有身体幅度、近身肘部与利落挥手的实现没有修改。这个页面观察的是原生待机本身的幅度。

主要文件：`preview/core/native-motion.js`（采样、校准与重定向）、`realtime/native-motion/`（独立预览和只读服务器）、`scripts/native-motion/`（单文件解码工具和浏览器验收）、`tests/native-motion.test.mjs`（无游戏素材也能运行的数学/边界测试）。

## 运行与复现

已有本机私有输出时：

```powershell
node realtime/native-motion/server.mjs --port 18789
node --test tests/native-motion.test.mjs
node scripts/native-motion/browser-acceptance.cjs
```

打开 `http://127.0.0.1:18789/native-motion/`。服务器只监听回环地址，只读 GET/HEAD；仅为单个动画 JSON 和单个 GLB 提供精确别名，不公开整个 outputs 目录。

解码工具使用 .NET 10 和 [CUE4Parse](https://github.com/FabianFG/CUE4Parse)，本轮源版本为 `990d4d7d4e0340a75a14323436d55568f1415e00`。需要 CUE4Parse-Natives 的 ACL DLL；构建需要相应 C++ 工具链及 ACL/RTM 依赖，不能只复制托管 DLL。Oodle 由解析库初始化。工具、构建产物和资源索引密钥均留在本机独立工具目录。

`scripts/native-motion/build-probe.ps1` 接受 `-Cue4ParseRoot`、`-DotNetExe` 和可选的 `-BuildDirectory`，把编译产物放到本机工具目录；`run-one.ps1` 接受 `-PaksDirectory`、`-PatchDirectory`、`-KeysJson`、`-ProbeDirectory`、`-DotNetExe` 和可选 `-OutputDirectory`。后者固定只导出本轮 Stand2 与配套角色网格，并拒绝覆盖已有片段。

公开源码不带游戏网格、动画、PMX、贴图、资源索引、资源密钥、工具二进制或本机账户路径。没有本机资产时预览会明确报缺少单段资源，不会自动从网络取得资产。

## 证据与限制

本机证据目录为 `outputs/native-motion-20261022/`，包含解码结果、源/目标哈希、实际浏览器全 121 帧测量、正/侧/背/斜视图截图。原生动画 SHA256 为 `9eb819beaef621f60b9177bb759c33ce07a9984f4f3487e12597f01de52f04f5`；灰模 GLB 为 `12a413728d09fc8ba05dacd70d9de5b962cb309b99f41995284c34149aed2d5b`；目标 PMX 为 `79b622d0a87ab61516d2c3008d241d9145daa905acbcbd29d070c68cc55fa437`。

最终本机验收（Chrome 156、ANGLE D3D11、RTX 5070 Ti Laptop）：

| 检查 | 结果 |
| --- | --- |
| 无资产单元/HTTP 边界测试 | 4/4 通过 |
| 实际双模型渲染 | 完整 121 帧，无非有限值、无浏览器异常 |
| PMX 骨长变化 | 0；仅腰部整体平移例外，不将平移误计为骨长 |
| 身体 13 个关键点位置差 | RMS 0.05921 / 最大 0.14731 PMX 单位，折合源厘米约 0.457 / 1.138 cm |
| 30 个手指关节点位置差 | RMS 0.10360 / 最大 0.14737 PMX 单位，折合约 0.800 / 1.138 cm |
| 首尾闭合 | 上述 13 个身体点位置差为 0 |
| 蒙皮变化 | 源网格与目标网格都验证实际顶点随姿态变化，不以骨坐标变化替代 |
| 暂停、继续 | 暂停 250 ms 时间及骨位置完全冻结；继续后时间前进 |
| 连续双模型播放 | 180 帧 / 4.149 秒，约 43.38 FPS；整帧 JS 驱动加渲染提交 P50 19.1 ms / P95 27.5 ms |

性能是本机两个模型、两个渲染上下文同时播放的窗口测量，并非独立重定向算法耗时，也不是语音链路延迟。这个指标不足以保证任何机器都能达到 60 FPS。原生轨迹是 30 Hz，通过线性位置插值和四元数球面插值显示。

复测期间有一次新浏览器在 90 秒加载等待阶段超时，未计入通过次数；原有已加载页面仍正常。随后独立重试加载约 34.0 秒，完整验收通过。首次模型/贴图/着色器准备时间仍较长，本轮没有证据把这次超时归因于某一项 GPU 或浏览器原因。此项与稳态播放数据分开记录。

这是一段原地待机的接入验证。尚未验证转身、行走根运动、接触型动作、外部道具、动作切换或调度中断；未调用云端模型。不能把这一段的成功外推为全游戏动作通用兼容。
