# 人物调度接入前，要先准备什么

日期：2026-10-23。本文是准备与分批接入说明，本轮没有修改运行动画或语音代码，也没有重新运行模型、云端对话或资源验收。

本文保留初始设计及起草时的源码情况，尤其第3节的具体缺口是当时快照。后续动作准备已做实际取放、表情与衔接实验，最新证据见[动作执行准备](action-execution-preparation-2026-10-23.md)；这些准备没有自动等同于正式人物导演、数学情绪或语音链路已经全部接入。

**不必先把整个资源库的说明全部补完，才能开始接系统。凡是准备交给系统自动使用的动作及组合，必须先有明确说明、实际可执行的进入和退出过程，以及当前模型上的验证。**其余素材继续留在浏览和手动预览范围，不让调度器碰运气调用。

完整接入指闲时、交谈、打断、回闲时、主动搭话都能走通，并继续保住语音、记忆和历史。它不等于第一天就开放所有动作；反过来，只有一次挥手演示通过，也不能称整套系统接好了。

## 1. 动作说明要做到多细，是否每个文件都写一遍

说明可以分层复用，共用规则不重复抄写；但不同场景的能力不能互相借用。

| 说明附在哪里 | 需要写清什么 | 举例 |
| --- | --- | --- |
| 一段原始素材 | 动哪些部位、时长、起止姿势、是否挪脚或转身、相关衣发 | “这个说话动作实际也动脚”，不能只按名字当上半身动作 |
| 一个完整行为 | 起势、持续、收回怎样组合；每个阶段怎样打断；做完停在哪里 | 阅读包含拿稳、看书、翻页、抬眼、恢复阅读，不只是一个文件 |
| 一个允许自动使用的版本 | 哪种坐站、持物与场景条件已经验过，哪里仍未知 | 空手站姿挥手通过，不代表坐着持书挥手也通过 |
| 一套表情 | 表达目的、影响哪些脸部部位、能否与说话口型共存、怎样退出 | 表情带有张嘴或连带变形时，要有已检查的说话版本 |
| 配套头发与裙摆 | 跟哪段身体动作、进度如何对应、能否承受当前身体调整 | 不能给身体换了动作，衣发仍从另一个动作的开头播放 |
| 一条中间过程 | 需要什么现场、每步怎样确认完成、取消时怎么处理 | 放书必须真的有可达桌面；书放稳后才能松手 |

例如几个站姿解释动作可以共用“空手、脚下场景不变、讲话中最多出现一次主要手势”的规则，各自再补实际入口、出口、衣发和验证范围。不能只给整个分类写“解释类，可打断”，然后自动放行所有文件。

**谁准备：**我们先用程序提取客观数据，再检查真实模型，形成可读说明及未来供调度器读取的同一份规则资料。用户不需要手工填写骨骼参数。

**依据是什么：**文件、时长、参与骨骼、运动范围和起终姿态可以批量测量；适合表达什么、是否能持物、哪里能停、是否穿插和动作是否自然，需要结合轨迹与实际画面确认。模型可以整理初稿，不能把文件名或自己的评价当成通过证据。

**判断不出来怎么办：**未知用途或未知组合保留为仅预览；可用部分先登记清楚。缺少实际退出路线就先制作或复用路线，不能只在说明中写一句“自然收回”。

## 2. 除了说明，还要准备哪些东西

| 准备项 | 实际要做什么 | 谁确认、依据是什么 | 缺少时怎么办 |
| --- | --- | --- | --- |
| 第一批使用范围 | 固定当前模型、交流方向和一组常用动作，明确先允许空手站姿还是也含坐姿持物 | 我们按当前资源与场景记录列清范围，并保留未开放清单 | 没验过的范围不自动启用；不能把限制悄悄藏起来 |
| 状态来源接线 | 把谁在说话、哪轮已取消、播放到哪里、最终情绪、生活精力、任务和内心意图传给人物 | 各已有负责程序提供事实；本地核对来源、时间与所属对话 | 语义没有结果可以少演；没有可靠身体或持物事实就不启动依赖它的新动作 |
| 当前身体和现场记录 | 统一知道手脚实际位置与运动、坐站、支撑、手里物体、桌椅位置 | 最终合成姿态与实际场景记录，不能只读“正在播哪个动画” | 先稳定当前可靠部分；不猜空手、不猜椅子在身后 |
| 一个最终控制入口 | 原生身体、原创补充、表情、口型、眨眼和衣发先分清控制范围，再统一写进模型 | 开发者核对各控制器接线，检查没有后一个控制器覆盖前一个结果 | 未接管的旧实验不能同时加入；只启用已统一的组合 |
| 可执行的稳定和退出过程 | 准备站立保持、倾听、收手，以及启用坐姿和持物所需的坐稳、持稳、放物等 | 实际动作、路线与每步完成条件，在模型上从不同阶段打断验证 | 没出口的长动作先不开；不能靠瞬间恢复标准姿势兜底 |
| 声音与动作的时间关系 | 声音先进入播放器，口型跟播放进度；语义动作只在所属话段内使用 | 播放程序、当前Qwen的建议与本地时机检查；现有播放证据是浏览器排程估计 | 指令迟到就跳过，不补演、不等它才发声；无逐词时间就不声称卡准某个字 |
| 一次要求的归属和撤销 | 知道动作属于哪轮回复或哪次活动，处理重复、改口、旧结果迟到以及第二个Qwen接续 | 现有对话取消事实加本地执行记录；真正开始才算开始执行 | 撤销后不复活；没做成不记成功，不破坏用户已接纳的纠正和历史 |
| 主动搭话与交谈退出 | 接好现有主动许可、首声前复核、被抢先开口时撤回；区分说完、等回答和可恢复活动 | 原业务系统决定能否说，本地决定身体配合；播放完不单独证明聊完 | 缺主动许可就不出声；结束不明先放松，别卡住或擅自判定用户离开 |
| 原因记录、验收与退回 | 显示选了什么、为什么拒绝、哪里失败；能关掉有问题的组合 | 对照事件记录、连续画面与同条件语音测量；通过记录对应具体模型和资源版本 | 该组合退回预览，保留已验证语音与动作；没有设备回采就不宣称扬声器实测 |

这些准备不全是写说明。主要包含三种工作：**把规则登记清楚，把当前缺少的执行能力补出来，再在真实模型上验过。**只有第一种完成，调度器仍然可能不知道怎样接、怎样停。

## 3. 当前最值得先处理的实际缺口

结合已核对的方案和控制器，优先处理以下事项；这是一份待做清单，不是本轮已完成的功能。

1. **先接真实状态，再决定表情。**当前D语音实验仍由Qwen选择表情，数学情绪基调尚未统一进入人物。还要区分真实生活精力与为了保证回答而临时采用的回复状态。
2. **先统一执行，再同时开多个控制器。**原生资源页、活动页和语音页分别能动，不代表把它们一起开就不会抢同一根骨骼或同一个嘴形。
3. **把局部连续过渡扩到实际要用的全身组合。**当前有手部保留速度的基础，但原生全身跨动作、支撑和衣发仍要逐组合接好。动作有起势、循环、收势，不代表任意时刻都能跳进收势。
4. **启用持物前先解决物体连续性。**书不能随双手距离缩放，也不能因为下一动作没声明它就消失。合书不等于放书；如果第一批不开放持物，这项可以后做，但持书活动也必须保持关闭。
5. **真正接通主动语音和交谈往返。**现有主动业务需要与当前双工输出协调，准备搭话、首声前取消、部分播放和回到闲时都要有实际流程。

脚能到达某个位置，只能证明这一步在骨骼范围内够得着，不能证明已经做过完整物理平衡或衣发碰撞验证。第一版先采用经过检查的固定场景与动作组合。

## 4. 我建议怎样安排顺序

### 先打通一组完整过程，同时整理其余资源

第一组可采用空手站姿：原生待机、注意用户、轻微倾听、少量明确手势、说话表情、收势、回到待机。先把状态来源、统一执行和打断保护接好。

第一条验收过程是：

> 待机 → 你开始说话 → 她注意并倾听 → 回复、口型和一次合适表达 → 在准备、主动作和收回阶段分别被打断 → 自然收住 → 继续倾听 → 合适时回到待机。

这一条通过只证明基础交谈流程打通。接着必须检查内心与事件驱动的闲时变化、交谈后的放松恢复，以及主动搭话准备时被你抢先开口。原有记忆、后台分析、第二个Qwen转交和历史记录仍按原规则运行；不为了人物方便缩短成假对话流程。

**谁决定可以进入下一组：**开发者用当前模型检查正常、打断、取消、失败与恢复的完整记录；连续观看确认幅度、近身肘部和利落挥手仍符合要求。云端真实对话要在后续获准的有界测试中另验，本次不新增调用。

**判断不出来怎么办：**保持该组为试验或预览，不开放更多组合来掩盖基础问题；必要时只关闭有问题的动作，不关闭整条已经可靠的语音链。

### 可以并行做的准备

- 批量提取整个素材库的文件、时长、骨骼和轨迹信息，形成待检查清单。
- 将资源分为“可自动使用、仅限已验场景、只供预览、缺少出口”，让当前覆盖范围可见。
- 检查更多表情的嘴形冲突、配套衣发和道具需要。
- 为后续坐起、转身、持书、放书准备中间过程和独立预览。
- 准备原因日志、连续录像、新旧对照和资源加载耗时测量。

其中“可自动使用”指具体获准版本，不是整个文件名一旦被打勾就处处能用。

### 后续逐组扩展

先扩坐姿交流与起坐，再扩持书阅读与放物，最后扩大到更多桌椅布置、连续活动和自然变体。每新增一组，都补它自己的进入、退出、中断和异常范围；共享规则可以复用，新增场景条件仍要检查。

各组要能在已有系统中共存，不能每加一组就靠切换独立演示页面才能使用。模型或骨骼绑定、关键轨迹、物体尺寸、控制方式改变时，相关组合重新检查；无需无差别重测完全无关的资源。

最终可以称为“约定范围内完整接入”的条件是：你要求的闲时与交谈往返、对话表现、主动搭话、打断恢复都已接通；数学状态、真实任务、语音与历史保护仍一致；所有获准自动使用的版本均有可执行说明和证据；未覆盖内容明确列出。是否已开放整个资源库，应另列覆盖情况，不能混在一句“全部完成”里。
