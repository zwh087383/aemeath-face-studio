# 完整动作库扩展：实施与验收记录

本轮在独立工作区 `face-library-expansion-20261027` 实施，基线为 `5b1f583556610da09e63d0eaf872340277dfd462`。原来的 `face` 工作区与私有资源作为只读来源。所有模型指令均为本地测试输入，没有调用云端，也没有借用其它测试批次额度。

## 交付口径

统一目录共 262 项能力：原有 73 项交流动作、76 项生活活动、109 组原生行为、1 项实际下巴接触，以及 3 项活动控制。76 项包括原来的全部 75 项，以及本次实质新增的“坐稳后移椅到桌前”。控制指令不算新增动画。原生来源仍完整登记 149 组、319 段，起势、中段、收势不会分别计成独立行为。需要外部场景的 35 组及被禁止的 5 组只有索引，没有模型可调用 ID。

`realtime/character-center/catalog.mjs` 从同一编译器产生浏览器目录，`scripts/character-center/build-catalog.mjs` 生成后端 JSON；两者的规范化内容摘要必须一致。模型看到的是共享条件表、效果表、时长表和变体表组成的精简目录，不会收到原生几何采样和私有资源正文。条件暂时不满足的动作仍然可见，以便模型选择先拿书或先坐下；执行时不会预先假定这些步骤成功。

## 一次动作怎样真正完成

| 环节 | 谁决定、依据是什么 | 做不到时怎样处理 |
| --- | --- | --- |
| 做什么、做几次、何时保持 | 模型使用统一目录，给动作顺序与许可；本地测试则明确标记为人工输入 | 不用关键词偷偷补动作，不加每轮次数或冷却限制 |
| 当前是否可以做 | 中枢检查当前姿态、实际脚/座位支撑、每只手、实际道具、来源有效期和目录版本 | 返回具体条件，不改变现场；后续依赖步骤不按预计成功继续 |
| 准备原生资源 | 缓存逐组读取，核对解压后的原始 JSON 字节摘要；同组并发请求复用 | 单组失败不清掉其他组；取消的准备结果不能接管人物 |
| 对齐现场 | 原生场景驱动器采样真实 PMX，并用实际椅面、桌面与脚目标进行几何核验 | 预检恢复当前显示，失败不落地；异步准备后重新检查现场 |
| 延长动作 | 只在得到许可后，播放器计算原速进入、可延长中段与原速退出 | 时间区间放不下完整过程就拒绝；整圈资源返回实际可达时长 |
| 持物和放下 | 手部与桌面的几何接触、低速释放条件和物品执行回执共同决定 | 模型说“放好了”无效；不会凭一句话更改物品归属 |
| 正常完成 | 播放器报告实际结束姿态、位置、持物和耗时 | 播放失败与正常完成分开；动画结束不代表后台业务完成 |

普通命令不附加新许可时，继续原速、单次、原有执行方式。数学情绪和精力只调制明确许可范围内的持续时间和局部表现，不会换成另一件事，也不缩小既有交流动作的身体幅度。

资源加载和异步几何准备各有 30 秒真实时间上限，防止一个永不返回的请求堵住队列。超时会撤销该命令及依赖它的同请求后续步骤，保留其它请求；过期结果不能再次获得人物控制。资源请求同时中止网络读取。这是准备阶段保护，不是长活动时长上限，也不使用加速预览的模拟时间来误判超时。

这条调制已经接回实时页面：身体读取与表情相同、已通过版本校验的数学状态，旧状态不能倒灌。生活活动得到 10–20 秒许可时，精力 0.15／0.85 对应 11.5／18.5 秒；原生 Thinking01 得到 6–15 秒许可时，对应区间的低／高目标可达 1 圈 6.4667 秒／4 圈 14.4667 秒。后者只能选整圈，不能声称支持任意精确秒数。所有时间都保留原速起收。

## 新接通的连续能力

生活活动中，坐姿倾听、坐姿放松、站姿阅读、坐姿阅读、桌前阅读、写字和打字具有明确可延长中段。拿物、翻页、开合电脑等事件不在循环窗口里。延长打字不会反复开电脑，暂停后也不重新开始拿物。总时长包括真实进入过渡；单个目标值不足时明确返回实际最短时长，区间上限不足时拒绝。

点头、摇头、侧头、注视与倾听的 `support-preserving` 变体只在获得许可后使用。它们保留当前座位、脚下支撑和握物的手。原来的默认站姿空手轨迹没有被直接套到坐姿上。

轻点下巴使用实际 PMX 下巴表面与当前头部变换求接触点，食指接近，其余手指收拢。嘴部发音时撤出接触空间，最后回到退出姿态。它是明确可选的新动作，不会因为问题中出现“思考”就自动触发。

站姿从分区桌面拿书、拿杯及放回时，根据实际物品距离使用有限前倾和骨盆前送，脚和物品保持真实位置；原近桌边轨迹不变。更远而不可达的目标在只读预检中拒绝。`pickup_box` 的现有语义是“从台面抱起物品”；单项检查明确布置台面箱子，不能把地上的箱子当作台面源。

在分区桌面放下展开的书时，先用 1.4 秒实际合拢，再走原有放置路线；这段时间同时计入准备估算、真实执行和取消过程。已经合上的书不增加此阶段。双手一直跟随真实封面握点，拿起后立即放回也不会重复叠加向前探身。模型可以看到物品是否展开及少量实际位置事实，判断执行条件仍由本地完成。

步行、跑跳和搬运在准备与开始时检查真实桌腿、桌面、椅面、椅背、箱子和平台。检查用实际 PMX 骨骼与扫过的路线，失败保留现场并返回原因。循环的每一圈重新检查下一圈；不因为第一圈安全便穿过后面的家具，也不暗中改成另一条路线。

实际画面检查又发现旧默认站位穿过椅面，因此入座不能只靠插值接过去。现在默认预览明确从“椅子已拉出、人物站在椅前”开始：先弯膝落座，双脚承重；再选择“坐稳后移椅到桌前”，让脚步、骨盆和椅子一起推进，桌子保持原位。站起时先退椅再起身。当前桌椅太紧、人物在侧后方或方向不对时，执行器说明所缺条件，不瞬移家具或把身体穿过椅子。初始布景不等于已实现“用手拉空椅子”；运行中的物体仍只能由实际执行回执改变。

## 开口、暂停、恢复与撤销

收到当前连接的真实 `speech_started` 后，客户端立即发本地注意事件。它不推测用户说了什么，只撤掉旧的待执行意图，并让当前真实生活活动到安全窗口暂停。正在落座或接触转移时，必要过程继续推进，不冻结在半空。重复的同一输入事件不会再次撤掉新一轮。

暂停保留活动令牌、实际进度、书的位置、握点、座位及电脑开合状态。稳定后可以在这些约束下回应。模型明确发出 `resume_activity` 才从原进度恢复；`finish_activity` 走原正常退出。它们必须使用当前令牌和 `append`，不能通过替换整项任务冒充恢复。

明确来源撤销或全局撤销仍然停止对应活动，不能借注意保留租约复活旧任务。音频停止不停止身体收势时钟。纯本地 VAD 暂定噪声仍走原音频暂停/恢复保护，不冻结身体；服务端已确认开口后又判输入无效时，身体保留注意暂停，等待明确恢复。

## 表情怎样跟随

数学系统继续拥有长期情绪。主态度决定主要眉眼和嘴角，次态度只提供有限的相容变化；冲突部位服从主态度。相同语义证据换一个 ID、更新身体阶段或换次态度，都不能无限续期。

身体配套脸读取当前实际执行阶段。持续活动读当前采样姿态，原生行为读实际片段与阶段，支持型交流读实际包络；取消和退出撤掉这一附加层。中性专注关联不会洗掉数学情绪。口型、眨眼、笑眼与疲劳眼睑继续在统一控制器合成，嘴部发音保有必要通道。

## 预览与复核

运行根目录 `Start-Full-Motion-Library.bat`，或：

```powershell
node realtime/library-expansion/server.mjs --port 18820 --asset-root F:/AI-Shared/model_test/face
```

浏览 `http://127.0.0.1:18820/library-expansion/`。页面支持分类、搜索、明确前置场景的单项检查、按当前现场执行、总时长与变体许可、暂停、时间回放、多个视角、开口转向、明确恢复和正常结束。可以导出执行记录及录制实际播放画面。

“单项预览”会明示并执行前置步骤，例如先落座、再取书。这是组件验收布景，不是模型自主选择，也不代表真实后台活动。页面的原速单次/原表情按钮只比较同一播放器内的许可与表情；完整旧代码性能对照使用另行冻结的基线源，不混淆二者。

## 验收证据与边界

逐项机器检查、浏览器实际模型检查和人工连续观感分别记账。原生衣发沿用现有绑定；数值可达、真实落脚和台面回执不自动等于所有镜头都没有穿插。最终人工审阅入口一直保留。

活动细节见 `library-activity-validation-20261027.md`，原生细节见 `native-library-integration-evidence-2026-10-27.md`。最终总表 `full-motion-library-catalog-and-acceptance-20261027.md` 由 `scripts/character-center/build-library-report.mjs` 从本轮结果生成；旧失败批次保留在独立输出目录，不覆盖为成功。性能记录包含相同动作、画幅、音频与交错批次顺序，并把首次绘制与预热后播放分开。机器上其它用户服务保持运行，记录每批 CPU、内存与渲染器；预缓冲音频的连续性检查不声称证明了真实云端流式网络、麦克风或扬声器听感。

本轮没有改 WAI 的检索、记忆纠正或历史交付实现；它们的离线回归与真实云端对话验收严格区分。模型能否自然使用扩展后的整库，仍需要后续单独授权的真实模型测试。

最终协议与既有双工保护回归为 246 项 Python 通过，中心、连续表情、生命周期及支持交流为 123 项 Node 通过。活动代理另完成 43 项旧入口回归、42 项活动专项和 10 项支持交流；后 10 项与中心集合重复，不把不同集合简单相加冒充独立覆盖量。具体逐项实体检查以总表及两个专项报告为准。

仍有明确的体验成本：复杂原生动作第一次准备可能需要数秒；Sit01 和 Weak_Sit 取消后仍要走必要源阶段。已测取消点到身体站稳分别最长约 6.4 秒和 10.72 秒。旧命令和语音不等这段过程才失效，但不能将其称为身体立即停下。逐项准备耗时和取消剩余时间见性能及原生报告。

具体新旧帧耗时、首次绘制与故障注入声音复测见 [本地性能记录](full-motion-library-performance-20261028.md)。前批高负载下出现过一次音频回调间隙，复测三项为零；两者均保留，不将复测覆盖成“历史全部通过”。
