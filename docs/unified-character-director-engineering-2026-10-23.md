# 人物为什么这样动，以及动作怎样自然地接起来

日期：2026-10-23。本文是详细方案，不是已经全部实现的功能清单。已核对现有程序和真实动作素材；本轮没有修改运行代码、调用云端语音或进行新的连续播放验收。

说明采用“当前情况 → 判断依据 → 具体选择 → 实际运动 → 出错处理”的写法。用户无需理解代码名和数学公式。这里讨论的时间初值都需要后续用真实角色调整；当前身体幅度、近身肘部和利落挥手保持。

本次补充：所有环节都写清**谁判断、依据是什么、判断不出来怎么办**。下面描述的是计划采用的完整做法；哪些已经有、哪些仍要补，在第16节逐项区分。旧文档与本文对判断来源、证据或未知情况的处理有差异时，以本次补充为准。

先把文中几种负责方讲清楚，后面不再用代码名字称呼它们：

| 负责方 | 负责什么 | 不替它做什么 |
| --- | --- | --- |
| 当前回复的Qwen | 理解你这句话与上下文，在回复中建议解释、招呼等交流表现；转交后由实际接着回复的Qwen负责 | 不测量手脚位置，不认定任务已经执行，不决定最终情绪数值 |
| 已有后台分析 | 继续理解事件、处境和需要消化的内容，沿用现有模型配置 | 不为每个动作新增一次模型请求，也不让快速首声等它 |
| WAI的数学与生活系统 | 计算情绪、关系、精力等持续状态 | 不直接指定每根骨头怎样动 |
| 语音和任务程序 | 报告输入、播放、取消以及任务实际运行情况 | 不把“说打算做”当成“已经做了” |
| 本地动作调度 | 根据上面已有结果，对照动作说明和当前身体，决定能否开始、怎样接、何时收回 | 不重新创造情绪，不每帧调用语言模型 |
| 动作制作与验收人员 | 我们先检查资源、测轨迹、制作使用说明，再连续看实际模型；你可直接评审观感 | 不要求你自己填骨骼参数，也不把模型口头评价当成验收 |

这里的“本地规则”是一张可检查的条件清单。例如“能否挥手”要查当前是否持物、有没有当前坐姿或站姿版本、手能否按已验证路线抬起、要求是否已撤回。每项保留“已满足、明确不满足、尚不知道”三种结果；尚不知道不当作通过。

不同依据冲突时，只让各自负责方判断自己的事：语音程序决定输入和取消；数学系统决定持续情绪；场景与身体记录决定手里有什么、能否移动。模型建议不能推翻这些事实。两个同类来源冲突，就先不用依赖这项事实的新动作，再向原负责方读取最新记录。

“判断不出来”也不等于什么都卡住：没有语义依据时少演一次；不知道身体能否接入时不启动新动作；已经在动的身体走已验证的稳定收势；声音继续由原语音流程管理。普通表演缺一项信息，不为此打断你追问。

## 1. 调度中心每次作决定前，究竟要知道什么

它需要同时知道六件事。

| 要知道的情况 | 从哪里获得 | 能据此决定什么 |
| --- | --- | --- |
| 刚才发生了什么 | 用户输入、模型回复过程、任务开始或结束、场景事件 | 这时是否需要回应、解释、转移注意 |
| 她现在是什么状态 | WAI 已有数学情绪、关系、生活状态 | 表情基调，动作偏温和还是活跃，自发动作是否应减少 |
| 现在交谈到哪一步 | 用户还在说、等待回复、角色正在说、等待用户回答 | 能不能分心，是否可以开始休闲 |
| 身体现在是什么样 | 当前已经显示出来的姿态与运动 | 是坐着还是站着；手在哪里、往哪里移动、移动多快 |
| 身边实际有什么 | 当前场景中的椅子、书、杯子及其位置 | 能否坐下、持物、放物；不能只凭素材库里存在就当它在场 |
| 刚刚做过什么 | 已经真正开始显示的动作记录 | 避免同一句反复点头、短时间重复挥手 |

这六件事不互相代替。开心不能证明现在适合挥手；模型说“我在想”不能证明手里应该出现书；用户发出一点声音也不能证明她已经听懂一句话。

情绪继续用现有数学系统。动作系统只读取结果，不另外积累一套情绪。还有一个需要纠正的现状：为了及时回答用户，现有回复通道会临时按“允许回答”的状态处理精力与醒睡；闲时表现应读取真实生活状态，不能因此让角色永远处于清醒状态。

**谁判断：**上表各来源先报告各自事实，本地动作调度负责把它们放在一起核对。它不靠语言模型想象身体，也不靠摄像头猜当前虚拟场景里有没有书。

**依据是什么：**每条消息都要知道来自哪次对话或哪项活动、何时更新、是否被撤销。身体位置取最终合成后准备显示的姿态及前后两帧的变化；物体取场景中的实际登记；“做过动作”取真正开始显示的记录，不取仅进入队列的记录。这里的显示记录仍是程序证据，不证明显示器或用户实际看到了。

**判断不出来怎么办：**缺少情绪更新时短暂保留上次有效基调，不编造情绪突变；没有用户位置时使用事先设定的交流方向，不声称正在追踪真人目光；不知道手里是否持物时，不安排需要空手的新动作。资料补齐后重新检查是否仍需要动作，不补演所有漏掉的反应。

## 2. 动作进入自动使用范围之前，需要说明哪些事情

每个动作都要补齐以下说明。不是只有“名称、时长、文件地址”。

| 必须说明 | 以挥手为例 |
| --- | --- |
| 它在表达什么 | 打招呼、告别或回应明确要求；不是赞同一项观点 |
| 什么理由可以调用它 | 用户要求挥手、已确认需要打招呼；心情好本身不够 |
| 哪些场景不适合 | 正在认真倾听、双手持物且无换手方案、说话对象已经离开 |
| 开始前身体要怎样 | 站姿版还是坐姿版；肩臂需要处于什么范围 |
| 具体使用哪些部位 | 手腕、前臂、肩、躯干、头；不能只看名字认为它只动手 |
| 会不会改变位置或支撑 | 是否转身、挪脚、起身；不能附带未请求的起立 |
| 需要什么物体 | 空手，或明确允许另一只手持物 |
| 分几个阶段 | 抬手准备、利落挥动、短暂停留、收回 |
| 哪些时刻可以停止 | 手已抬起如何收回，正在摆动如何减速，持物时如何保持 |
| 动作结束后是什么状态 | 手回到哪个范围，身体仍站着或坐着 |
| 配什么表情和衣发 | 同一交流目的的表情，以及与身体运动匹配的头发裙摆 |
| 已经验证过什么 | 在当前模型上能进入、能退出、能被打断，没有明显骨骼跳变 |

这些说明由我们检查素材、程序和实际画面后登记。模型可以提出“打招呼”的要求，但不能自己声称某个未检查动作已经适合坐姿、持物或任意中断。

现有游戏资源里有漂亮的完整轨迹，但这些使用条件并没有都随资源一起导出。因此，“能在浏览页播放”与“能随时自动调用”是两种能力。

此前资源检查发现：原生“思考起势”包含很大的手臂变化，不能把它当成微小思考动作；原生“展手起势”会动到脚，也不能直接截掉下半身就认为获得了坐姿展手。

**谁判断：**动作制作与验收人员在准备素材时登记；本地程序使用这些登记结果。语言模型可帮助找相似资源或整理说明，但无权自动宣布“这个动作已经验证适合坐姿”。

**依据是什么：**先用目录和名称找到素材，再检查实际轨迹、参与部位、配套衣发及道具要求，最后在当前模型上连续看进入、主体、退出和不同阶段打断。记录具体通过了哪些起始姿势和组合；“站着空手通过”不自动扩大为“坐着拿书也通过”。

**判断不出来怎么办：**语义、支撑或退出方式未确认的资源，继续留在手动预览范围，不自动选用。缺少收势的长动作不先放进去再指望模型临场救场；先补出口、验证组合或使用已有可控版本。

## 3. 之前说的“候选”，究竟从哪里产生

“候选”就是：针对眼前这件事，先列出几种有理由采用的表现。这个清单应当很短，而且每一项都要能说出理由。

| 发生的事 | 首先考虑的表现 | 不应该顺便加入的表现 |
| --- | --- | --- |
| 检测到用户开始说话 | 抬眼、转头、收住分心动作、保持可倾听姿态 | 未理解内容就赞同、完整挥手、惊讶 |
| 用户明确要求挥手 | 当前姿态能够完成的挥手版本 | 点头冒充挥手，起身后才勉强挥手 |
| 回复正在解释一件事 | 经过确认的解释手势、配套眉眼，或者安静说明 | 所有“看起来很活泼”的动作 |
| 系统开始一个真实后台任务 | 安静专注、视线收束、一次进入专注的姿态调整 | 自动生成书、假装操作不存在的电脑 |
| 有明确的思考或消化需要 | 短暂思考表现，或维持专注 | 每次状态刷新都重新托腮 |
| 真实情绪变化 | 调整脸部基调；必要时一次克制的小反应 | 把高兴直接变成跳跃，把高唤醒直接当惊讶 |
| 精力降低 | 更舒服的姿态、减少自发大动作 | 自动喝水、睡觉、反复打呵欠 |
| 交谈明确告一段落 | 恢复之前有效的活动，或安静休息 | 不检查现场就重演拿书、起身或坐下 |

内心活动可以影响这些选择。例如“继续消化刚才的事”让专注姿态更合适，“等待用户”让可接话的保持更合适。但内心一条倾向不能单独批准开口、创造任务或创造道具。

持续状态和新事件也要分开。任务持续运行一分钟，是继续维持专注，不是重复六十次“开始思考”。开心持续一分钟，是保留温和表情，不是每隔几秒挥手一次。

已经开始的长活动则靠自身过程延续。例如持书活动可以包含阅读、移动视线、翻页和持稳。这些是同一活动的连续部分，不需要语言模型逐次发出“翻页”。

下面逐项说明表中八种情况从哪里得到。它们是八类依据，不是八次模型调用。

### 3.1 检测到用户开始说话

**谁判断：**复用现有Qwen语音链提供的开始发声通知；随后由当前回复的Qwen理解话中意思。本地动作调度只负责把早期信号变成轻微注意变化。

**依据是什么：**开始发声只能说明输入出现了，不能证明你在叫她、已经说完或者她已经理解。后续是否为有效输入，仍按语音链的确认结果；“爱弥斯，过来听我说”与“别人刚才喊爱弥斯”要结合完整内容和上下文区分。

**判断不出来怎么办：**先看向交互方向，不赞同、不挥手、不做惊讶。如果原语音流程认定是无效干扰，就撤回这次轻注意变化；恢复或取消声音仍由原语音流程决定。

### 3.2 用户明确要求挥手

**谁判断：**当前回复的Qwen理解请求，并通过已有动作工具建议挥手；本地规则决定能否实际执行。不另加一个先判断动作、再允许Qwen说话的模型步骤。

**依据是什么：**结合本轮话语和上下文，区分“给我挥手”“不要挥手”“挥手是什么意思”。本地还要检查这次要求未撤销、动作版本适合当前姿态、手部可用、入口与出口已经验证。模型声称自己“很确定”不替代这些检查。

**判断不出来怎么办：**Qwen没给出可靠意图就不靠“挥手”两个字补猜；参数不合要求或对应旧对话就不用。明确请求但身体暂不可用，可在本轮仍有效且存在已验证换手或放物过程时稍后执行；若无法执行，要记录未完成，不能用点头冒充。普通附带手势则可以直接略过。

### 3.3 回复正在解释一件事

**谁判断：**正在生成这一段回答的Qwen建议解释类表现，本地规则检查时机和身体。旧字幕关键词规则不同时充当第二个自动发令者。

**依据是什么：**建议必须属于正在播放或即将播放的这段话；身体能做、同类表现没有刚刚重复、语义时机仍在，才使用。只出现“因为”“首先”不足以确认需要手势。

**判断不出来怎么办：**照常说话，保持适合当前情绪的脸和交流视线。建议来晚了不追到下一句话补演。当前Qwen每个响应最多附带一组动作表情，没有词语的发音时间；因此先做段内配合，不声称能准确卡住“第二点”三个字。

### 3.4 系统开始真实后台任务

**谁判断：**执行任务的程序报告实际开始、完成、失败或取消，本地规则判断是否值得表现。模型说“我查一下”只表示打算。

**依据是什么：**具体任务已经从待执行进入运行，并且仍与当前需要有关。制作时列清哪些任务适合外显：为你查资料、整理方案可以；保存日志、维护缓存、普通记忆落盘不需要。非常短的任务可以完全不做准备动作。

**判断不出来怎么办：**没有实际开始记录就不演“已经在查”；任务状态未知时不新开任务专属姿态，向任务程序核对。任务完成或取消后不继续保留原来的专注理由；身体仍需正常收势。

### 3.5 有明确的思考或消化需要

**谁判断：**已有后台分析与内心状态规则提供“具体需要处理什么”的依据；你明确要求思考时，也可由当前Qwen理解。本地规则决定这件事是否需要外显。

**依据是什么：**例如你要求比较两个方案，或后台确实留下需要继续梳理某项结果的意图。要带具体内容、来源和当前是否仍有效。仅仅请求没有返回，只能证明还在等待，不能证明模型正在深思，也不能读取模型内部的思考过程。

**判断不出来怎么办：**安静等待，避免无依据的托腮。后台分析很晚才到，要重新检查原话题是否仍在、你是否又开口；旧意图失效就丢弃。同一件事继续处理，只维持一次专注，不反复演“刚开始想”。

### 3.6 真实情绪变化

**谁判断：**已有后台模型可能先理解事件种类和影响强度；现有数学系统结合原状态、关系与时间计算最终情绪；本地动作规则把结果变成表情变化。

**依据是什么：**读取数学系统已经更新的完整状态及其变化，不直接拿模型输出的“赞许”“批评”当脸部命令。小变化平缓调整基调；明显变化才考虑一次短反应。同一次更新涉及多个情绪数值，也只视为同一次变化。

**判断不出来怎么办：**后台分类失败或未到，就使用数学系统当前已有的有效状态，不在动作端另造一个“开心”结论。无法确认多条变化是否来自同一次更新时，只更新持续表情，不派发独立惊讶等动作。具体变化门槛要用真实场景调试，不能由模型临时改门槛。

### 3.7 精力降低

**谁判断：**读取当前启用的生活与精力计算，本地规则决定何时改变表现，无需额外调用Qwen判断“累不累”。

**依据是什么：**明确采用哪条生活计算来源，检查精力是否持续处于偏低范围，以及是否真正恢复。为了保证快速回答而临时提高的“允许回复”数值，不当作人物真实生活精力。

**判断不出来怎么办：**来源不一致或暂缺时，不触发打哈欠、睡觉等强表现，保留当前可交流姿态。判断为低精力后先减少自发大动作；恢复要另设恢复条件，避免数值在边界附近来回变化时反复切换。范围和持续时间在后续验收中确定。

### 3.8 交谈明确告一段落

**谁判断：**当前Qwen或已有处境分析可判断结束、暂停、追问等语义；语音与对话程序核实输入、输出和待续回复；本地调度决定身体是否可放松或恢复活动。

**依据是什么：**“先这样，我去忙了”与“谢谢，不过还有个问题”意义不同。即使语义像结束，也要确认没有新输入、未播完声音、第二段回复或正在等你回答的问题。现有处境分析只是参考，尚无一个已经接好的统一人物退场判断。

**判断不出来怎么办：**先收手、放松肩部、减少持续注视，保留可接话状态；不因几秒沉默就判定你离开，也不无限僵硬盯住你。没有明确结束语时，由本地规则结合持续安静、无待回复事项和活动可接入性逐步恢复可随时中断的轻活动；这个过程不宣称“对话已结束”。具体阶段见第12节。

## 4. 哪些可能的表现会被筛掉

先排除根本不适合或做不到的，再比较剩下的。不能靠“很符合情绪”补偿“手正在拿东西”。

以“她坐着双手拿书，你叫她”为例：

| 可能的表现 | 判断结果 | 原因 |
| --- | --- | --- |
| 抬眼看你 | 保留 | 能迅速回应到场，而且不需要放书 |
| 轻微转头看你 | 身体与书没有冲突时保留 | 头部可先动，不必等双手空闲 |
| 继续保持书的位置 | 保留 | 保住当前现场，避免手和书突然改变 |
| 赞同地点头 | 排除 | 目前只知道你在叫她，还不知道你说的内容 |
| 双手展开欢迎 | 排除 | 双手拿着书，不能直接展开 |
| 单手挥手 | 暂不采用 | 只有确实验证过另一只手能稳定持书、且需要招呼时才考虑 |
| 站起来迎接 | 排除 | 叫她不等于要求起身，也不应附带大幅转场 |
| 突然惊讶 | 排除 | 没有惊讶的内容依据 |

留下的是“注意你，同时保持坐姿和书”。随后你说“给我挥个手”，才增加明确挥手需求，再决定是否能用一只手稳定持书、是否应先把书放低。

一次选择还要检查时机。表达“这一点”的手势，如果这句话早已说过去，就直接放弃，不能排队排到下一句话突然做出来。

旧的要求也不能继续排队。你已经改口说“算了”，刚刚加载完成的挥手不能又开始。

**谁判断：**本地动作调度按固定顺序检查；语义含义由模型提供，身体是否允许由身体与场景记录提供。停止或取消事实优先于旧模型建议。

**依据是什么：**先查要求还有效，再查是否适合当前交流，再查动作是否有已验版本、姿态与持物是否满足，最后查重复次数和时机。相同来源的重复消息只算一次。完整动作使用说明没有写明“允许双手持书”，就不能把沉默当作允许。

**判断不出来怎么办：**把“明确不适合”和“信息不够”分别记录。前者不用，后者只暂缓依赖该信息的选择；无关的口型、呼吸和已验证收势继续。一次筛选没有通过，不自动升级成让另一个模型重新猜。用户明确动作请求未完成时保留这个事实，不能记成执行成功。

## 5. 多个动作都合适，最后怎样选

比较顺序如下：

1. 优先满足当前明确的交流需要。用户要求挥手，不能因为保持姿态更省力就装作已经完成。
2. 在满足需要的版本中，优先从当前姿态容易接过去的。
3. 尽量延续当前活动和身体位置，避免无理由的站起、坐下、拿起、放下。
4. 再用情绪、精力和关系选择适合的表达风格。
5. 最近重复过的降低优先级。
6. 同样适合时优先已验证的游戏原生资源。
7. 如果新动作没有明显收益，就继续保持。

例如，她站着空手，确实需要表现一次思考。站姿思考可能入选；坐姿思考因缺少坐姿现场而被排除；展手解释因目的不同而被排除；长篇待机演出因过于占时或没有可靠退出方式而被排除。

即使站姿思考语义最合适，当前手位与它的入场姿态相差太大、又没有验证过的过渡，也不能直接开播。此时可以采用经过确认的较轻表达，或者保持专注。

情绪影响“怎样表达”，不是凭空扩大动作范围。疲倦时可以更少自发挥手；但已经决定按你的要求做利落挥手，就保留现有幅度和主挥动速度。若以后需要疲倦版，要单独制作和验收，不能临时把全身动作慢放。

**谁判断：**本地调度按上面顺序比较。模型只提供想表达的意思；“哪个文件更好接”不用模型评选。

**依据是什么：**交流目的是否吻合、当前手脚与动作入口的差异、是否需要额外起坐或放物、最近是否重复，以及已验证的情绪风格版本。情绪只能在已适合的版本中影响选择，不能补偿没有退出路线或双手已占用。

**判断不出来怎么办：**两个版本同样合适时，优先延续当前正在做的，再选较少改变现场的已验证原生版本；不为了变化不停抽签。没有版本能满足明确要求时记录未完成，不播放近似动作冒充；对于可有可无的表达，直接保持也是正常结果。

**选定后什么时候再判断：**已经开始的表达，不因情绪小幅刷新或另一个版本略占优势就更换。用户有新要求或取消、现场条件失效时才重新检查；新的理由不紧急，就等当前动作到已登记可让出的阶段再处理。没有新理由时，阶段结束只完成原有流程，不凭空再选一次。需要立即打断的情况按第11节收势，避免两个动作来回抢身体。

## 6. 两个动作之间怎样接得自然

首先要记录的不是“上一段叫什么”，而是当前画面中的实际情况：手的位置、手朝哪个方向运动、速度多少，身体重心在哪里，哪只脚在支撑，手里拿着什么。

然后分两种情况。

### 能直接接过去

例如空手站立时，从一种小幅交流姿态接到另一种。

程序会保留切换瞬间的位置和速度，让新动作逐渐接管。手正在向外移动时，不会在切换瞬间突然反向；它可以沿原方向继续很短一段，减速，再接入新的轨迹。

这也不是简单把整个动作放慢。调整主要发生在衔接处，后面的原生主动作按原节奏继续。因此利落挥手仍然利落。

具体衔接用多久，要看双方姿态差、速度差和中间路径。差异小可以短，差异大可能需要更长，或者根本不能直接接。我们会计算几个允许的衔接时长，检查手脚有没有越界、持物是否稳定，再选最短可用的。时间拉长也不一定更好：手原来运动很快，拉得太长反而可能多滑出去。

这种保留当前运动后再接入目标的做法已有成熟动画方法参考，现有手部控制器也有可复用实现；需要推广到原生全身。[Epic 官方动画过渡说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-blueprint-blend-nodes-in-unreal-engine)

### 不能直接接过去

必须执行有意义的中间过程：

| 当前状态 → 想做的事 | 需要的过程 |
| --- | --- |
| 坐着 → 站姿动作 | 优先找坐姿版本；确实需要站起时才走起身过程 |
| 双手拿书 → 双手摊开 | 先有可靠放书过程，或换成能够持书的表达 |
| 转身中 → 面向你倾听 | 保留正在发生的转动和落脚，接到可停的位置，再调整朝向 |
| 正在落座 → 回应用户 | 眼神先回应，身体继续完成必要落座，不停在半空 |
| 手在脸边 → 快速收回 | 走经过检查的近身回收路线，避开头发和袖口，不把肘部往外顶 |

所谓中间过程不能临时随便编。它需要和普通动作一样，说明从哪里开始、怎样走、到哪里结束，以及中途如何停止。

### 为什么不能只判断“都是站姿”

前一轮真实素材计算发现：原生游戏待机和一些剧情动作的起始姿态，右前臂相差约74度、右手约109度。都站着，手臂却不是同一种准备姿态。

另一方面，原生坐姿说话的起势和循环，姿态几乎相同，但衔接处仍有约4度/秒的局部角速度差。这说明还要检查运动方向和速度。

这些数字来自源骨架轨迹，不代表目标模型已经完成了过渡验收。它们能确定的是：一个固定的“混合0.2秒”不能解决所有素材之间的衔接。

**谁判断：**动作制作阶段由我们检查和试调可用的衔接范围；运行时由本地动画程序在这些范围内计算、选择。语言模型不负责计算路线，也不批准一个没验过的动作拼接。

**依据是什么：**取当前最终合成后准备显示的手脚位置、方向和运动变化，与目标动作允许的入口比较；同时查支撑、持物和已登记出口。运行时只尝试预先限定的少量路线与时长，不无限搜索。检查入口、中途和结束，不只比较两张静止姿态。当前手部已有部分运动记录，但统一的全身记录仍待补；用于观察的最终姿态也不能再重复施加一遍同样的骨骼修正。

**判断不出来怎么办：**读不到新鲜身体状态或没有可用路径，就不启动这个复杂转场。当前动作按已登记出口收稳，正在落脚或落座的必要过程先完成，空出的眼神和口型可以先回应。仍找不到可验证出口，就标出该动作异常并停止新增冲突动作，不能宣称程序能自动解出任意姿势的无穿插路径。后续恢复按第14节处理，不靠瞬间归位。

## 7. 手脚、道具、头发和裙摆怎样保持一致

脚正在支撑身体时，地面的接触位置要保持。身体可以晃、骨盆可以调整，但不能因为上半身换动作就让鞋底在地上滑。如果腿已经够不到原位置，应选择实际踏步，而不是拉长骨头。

坐姿也是一样：椅子的位置和骨盆支撑关系必须保留。切换交流手势不应自动站起。

书或杯子要有固定大小和明确握点。单手拿物时，物体跟随正确握点；双手拿书时，两手配合书的固定尺寸。现有程序会按双手距离缩放书，这只能作为早期显示办法，需要改掉才能真正约束持物。

从手里放到桌上，要等物体已经接近正确位置、方向和速度都合适，才转为桌面支撑。不能提前松手，也不能后面再突然跳到桌上。

头发和裙摆应跟随所选身体动作的同一阶段。身体切到下一段时，衣发不能各自从头开始。已经烘焙成完整运动的衣发，也不能再把同一运动叠加一次。

如果我们为了持物或脚底稳定，对身体做了较大调整，原生衣发可能不再完全匹配。这种组合要重新看实际模型。当前没有完整的实时碰撞求解，不能保证任意组合都绝不穿插；应该保留经过验证的组合，并把不适合的组合排除。

**谁判断：**场景程序记录物体、桌椅和支撑关系；本地动画程序检查动作过程中是否维持这些关系。制作与验收人员确认具体组合是否适用于当前模型。

**依据是什么：**动作说明登记哪只脚应支撑、哪只手应抓哪个位置，实际位置与速度用于检查。放物要同时接近正确承接点、方向合适、相对速度足够低；只等“放物动画播到第几秒”不算已经放好。头发裙摆查看是否有同动作同阶段的配套资源，以及身体修改是否超出该组合验过的范围。这里只讨论虚拟场景中已登记的物体，不新增现实房间物品识别。

**判断不出来怎么办：**不知道物体是否放稳，就不宣布手已经空闲；不知道脚底支撑，就不开始依赖那只脚的新动作。继续最后可信的握持或支撑，并走已验证的稳定过程。衣发组合未验证时换兼容组合或拒绝该次新动作，不能靠缩小全身幅度掩盖。自动距离检查只能发现部分问题，不能替代连续画面的穿插验收。

## 8. 表情怎样与动作成为同一次表达

先确定她正在做什么交流，再一起选身体和脸。

解释时，手势、眉眼、视线属于同一个表达。手开始准备时，眉眼可以稍早有变化；主手势出现时表情达到主要强度；手收回后，脸逐渐回到当前情绪基调。不是给身体随便配一个“开心”。

持续情绪和短表情分开。平时温和的脸是底层；一句话中的疑问、理解、强调是短表达。短表达结束后回到底层，不是每次都回到毫无表情的脸。

如果身体动作因持物等原因被拒绝，依赖这个动作的整套强表情也不能先演出来。独立的“注意到你”的轻反应可以保留。

表情自身也要连续。半个笑容还没形成时被打断，应从现在的笑容程度慢慢收回，不能先跳到完整笑容再退，或者瞬间清空。

原生表情并不都是完整动画。此前查到的17个角色表情主要是固定形状配方，我们还需要安排怎样出现、保持多久、怎样退出。

有些“开心”“惊讶”配方还包含张嘴或特定元音形状。她正在说话时，不能直接把整张脸叠上去，否则会盖住口型。应使用保留眉眼、允许嘴角变化的说话版本，嘴的发音部分继续跟随声音。

**谁判断：**当前Qwen或有效事件提供这次交流目的；数学情绪系统给持续基调；本地调度按预先确认的身体与脸部组合安排先后和强弱。制作时由我们检查每个表情实际改了哪些眉眼和嘴形，不能只按“开心”这个名字使用。

**依据是什么：**先看这次目的是否有依据，再看身体动作是否获准、实际开始到哪一阶段，以及播放器是否处于说话中。身体和强表情作为一次表达一起决定；嘴的发音部分留给口型。原生固定脸形需要另有出现、保持、退出过程，不能把文件时长当成已有动态演出。

**判断不出来怎么办：**没有可靠意图就保留当前情绪基调，不猜惊讶或赞同。没有确认过的说话表情版本，只有已核实不影响发音嘴形的部分才可保留；如果配方包含连带变形、无法可靠拆开，就整套略过，改用已经验证的眉眼版本，不能凭名称猜哪里是嘴。身体拒绝后，依赖它的强表情也撤回；独立的轻注意反应仍可保留。取消从脸当前已经变化到的程度退回，不清空数学情绪。

## 9. 视线、眨眼和小动作怎样不显得机械

看向谁必须有实际目标：用户的位置或固定交互方向、当前拿着的物体、真实存在的场景变化。不能随便每几秒换一个方向。

用户叫她时，眼睛可以先过去，头稍后跟进；如果角度很大，眼睛和头不应无限扭过去，而应在允许身体转向时安排转身。

小幅视线移动可以发生在当前目标附近，但不等于她每次都发现了一个新东西。正在听用户，也不用一直完全不眨眼地盯着。

眨眼属于持续的生理表现，不消耗一次“交流手势”的机会。专门闭眼或眨单眼的表情出现时，普通眨眼不要再叠上去。

小动作也要有理由。调整姿态可以来自刚结束活动、精力状态改变、当前姿态不再适合接话。不能只因为上次小动作已经过去四秒，就又挠头一次。

次数限制只是上限，额度恢复不会自动触发动作。持续安静陪伴也是正常结果。

第一版可用下面的节奏作为试调起点，而不是当成定时表：

| 情况 | 初始限制 | 可以越过的情况 |
| --- | --- | --- |
| 自发小反应 | 最多积攒两次机会，平均每4秒恢复一次；同类至少隔8秒 | 用户明确要求，但仍不能重复执行同一请求 |
| 说话主要手势 | 最多积攒两次机会；每实际播放6秒恢复一次；同一表达目的最多一次 | 新的明确动作要求；声音暂停不积攒待补演动作 |
| 等回复的准备动作 | 一轮最多一次，即使转交第二个模型也不重置 | 新的用户要求另行判断 |
| 换一种休闲活动 | 两次新活动开始先至少隔20秒，进入稳定活动后先保持8秒 | 用户到场、明确要求、活动被撤销 |

必要收势不受次数限制。当前动作没能开始显示，不消耗这次额度；已经显示过的不能因为被打断就立刻重新补做。

**谁判断：**场景和当前交流提供视线目标，本地程序控制眼头配合、眨眼和次数限制。小动作的理由来自有效事件、生活状态或当前活动，不让模型逐次批准眨眼。

**依据是什么：**先看目标有没有实际位置，再看眼睛和头允许转到哪里、当前姿势是否支持身体跟转。没有用户定位时使用固定交流方向，不能说已经追踪到真人。普通眨眼参考上次眨眼与当前眼睑是否正被专门表情占用；小动作还要检查身体部位可用、最近实际做过什么。次数恢复只说明“允许”，不构成“应该做”。

**判断不出来怎么办：**目标丢失时回到仍有效的活动目标或舒适前方，不追踪旧位置。小动作理由不足就不新增，正常眨眼、已验证呼吸和必要收势继续。次数记录丢失时按最近可能已经做过处理，先不补发；声音恢复后也不补演暂停期间积攒的手势。

## 10. 声音、口型、字幕和动作怎样同时运行

声音准备好后，优先进入播放器。动作选择、模型加载和身体转场都不放在这条路前面等待。

口型跟随播放器当前正在走到的声音位置，不跟随音频刚收到的时间。字幕可能先到或后到，不能看到几个字就立即张嘴。

当前口型根据音量和几个频段估计开合、圆唇和横展，成本低，但还不是准确识别每个音素。目前没有专门识别双唇闭合音的机制。可以先保持这条便宜路径，以后再替换成更精确的口型分析，播放优先级不变。

当前播放位置由浏览器排程估计，不能直接说是扬声器实测。若要测用户真正听到声音和嘴形的差异，还需要录音或设备回采。

语义动作与声音对齐分三种处理：

| 信息情况 | 动作怎样处理 |
| --- | --- |
| 以后具备某个词或短语的可靠发音时间 | 才启用提前准备、主要动作落在对应位置；当前工具没有提供这项信息 |
| 只知道属于这一段话 | 做段内合适的表达，不声称精确卡住某个字 |
| 字幕或工具命令来得太晚 | 有经过检查的短准备版本就用，否则略过，不挪到下一句话补演 |

先说一句再转交第二个Qwen时，两段仍是一轮完整回复。第一段声音结束，不马上回闲时、不重新获得一轮手势次数；等待第二段时也不反复做“我在思考”。

**谁判断：**播放器报告声音进度，当前Qwen建议表达目的，本地调度判断此刻还能否配合。口型由本地音频分析与播放位置驱动；已有后台分析继续并行，不再增加一个先审回答再允许开播的模型。

**依据是什么：**检查动作属于哪段回复、该段是否开始播放、是否暂停、是否已经取消。当前每个Qwen响应最多附带一组动作和表情，既没有逐句计划，也没有词时间，因此不把它解释成整段连续动作脚本。播放器现有时间是浏览器排程估计，画面可以据此跟随，但不能冒充扬声器实测或用户已听到的证明。

**判断不出来怎么办：**语义指令没来就正常说话，不猜大动作；晚到且过时就略过。播放器暂停或进度失去可信依据时，不按墙上时间继续追赶发音嘴形和语义手势，嘴形平缓回到不发音状态；必要收势仍可按本地时间完成。声音的恢复由播放程序决定，取得新进度后重新对齐，不快速补演。转交第二个Qwen不重复发放准备动作机会。

## 11. 用户打断时，具体发生什么

先区分疑似声音和正式打断。

疑似声音出现时，现有语音宿主可能临时暂停。人物可以转移注意，但不能自行宣布新话轮已经成立，也不能自己恢复或永久取消旧声音。后续由原语音链判断是无效干扰还是有效输入。

确认有效打断后，同时进行：

1. 后面尚未开始的旧动作取消；迟到的旧命令也不再执行。
2. 旧声音按宿主规则停止，确认播放器已经清掉对应排程。
3. 当前身体保留位置、速度和持物，进入必要收势。
4. 眼神、倾听和新回复可以使用已经空出的部位，不等全身复位。
5. 已经接纳的用户纠正保留，不因旧回答取消而删除。

例如挥手中被打断：手不会瞬间回到身体旁，也不把剩下的挥手全部演完。它从当前摆动方向减速，沿已经检查过的近身路线收回。

新回复先准备好时可以先说。若手还在收回，就先用口型和兼容眉眼，不强塞另一个手势。

如果收回过程超过预计时间，记录是哪一部分还没让出，继续必要的稳定过程。不能为了“按时结束”突然清空姿态或道具。

**谁判断：**现有语音宿主决定疑似输入是否有效，以及旧声音暂停、恢复还是取消；动作调度决定身体怎样让出。输入内容和记忆纠正仍由原对话与历史流程接纳，动作系统没有删除它们的权限。

**依据是什么：**先看语音流程的确认与取消记录，再查旧动作属于哪次回复；身体是否可让出，取当前动作阶段、位置、速度、持物和支撑，而不是看声音是否已经停止。正在听到的是新输入，不必等最终文字全部确认才允许眼神注意；但不能把这种早期注意当成已经理解。

**判断不出来怎么办：**疑似输入期间保留原回复的归属，等待语音链裁定，不自行永久取消或恢复。身体迟迟未收好时，按该动作预先登记的异常出口处理，停止安排新冲突手势，空闲部位和新语音仍可回应。每种动作必须有让出时限和失败办法，不能无限显示“收势中”；时限到不代表可以瞬移。语音裁定长期未回则交给原语音故障流程，人物不补造有效输入。

## 12. 交谈结束后，怎样回到闲时

要分四件事：

- 模型已经生成完。
- 声音已经播放完。
- 这轮回复全部结束，包括可能的第二段。
- 当前交谈是否已经允许转回休闲。

只有前面几项成立，还不代表第四项成立。她刚问你一个问题，即使自己说完了，也应保留接话状态。

但接话不等于僵硬盯着你。声音结束后可以收手、放松肩部、降低持续注视；用户回答时再及时注意。这个放松过程不用等后台历史保存完成。

真正恢复活动前，再检查：

1. 之前的活动是否还有效，是否被你取消。
2. 书、杯子、椅子是否还在原来可接入的位置。
3. 当前姿态能否从一个合理阶段继续。
4. 你是否已经开始新的输入，或还有未完成的回复。

检查通过就接回原活动，例如继续持书，不重新演一遍拿书。检查失败就选择当前能做的安静保持或其他允许活动。

后台真实任务的恢复仍按WAI业务规则处理。人物可以先放松，不能因为动画继续了就宣称任务已经恢复或完成。

**谁判断：**当前Qwen或已有处境分析提供结束、暂停或追问的意思；对话与播放程序核实还剩什么；本地人物调度决定放松程度与活动接入；后台任务程序单独决定业务能否恢复。

**依据是什么：**把“我说完了”“整轮回复结束了”“还在等你回答”“原活动可以继续”分别确认。追问依据可以来自本轮语义建议或已确认对话记录；当前单次表情动作工具尚未提供完整的等待回答、结束交谈标记，需要补足，不能见到问号就认定永远等待。原活动要核对当前物体位置、活动是否取消、上次停在哪个可继续阶段。

**判断不出来怎么办：**不等后台分析也可以先收手、松肩、减少持续注视；不据此宣布交谈结束。先采用以下分阶段试调规则，所有时间是待测起点，任一新输入都会重新注意用户：

| 当前事实 | 谁作最后判断 | 初步处理 |
| --- | --- | --- |
| 本轮声音已停止，但仍有下一段回复 | 对话与播放程序确认，本地调度配合 | 可以收手放松，维持接话状态，不开新休闲活动 |
| 全轮已结束，刚问过你或语义不明 | 本地规则读取对话记录 | 先保持可接话；安静约3秒后可逐渐放松，不能强制盯住 |
| 全轮结束、持续安静约10秒，仍无明确结束语 | 本地规则核对没有新输入或待出声回复 | 可进入低强度陪伴；原有持书等活动若仍有效且可立即让出，可恢复很轻的部分，不启动新的长表演，也不宣告你已离开 |
| 已理解明确暂停交谈，输出也结束 | 本地规则最后核对现场 | 原活动条件满足则从合理阶段接回，仍能随时被新输入打断 |
| 旧活动取消、道具改变或现场不明 | 活动与场景程序报告，本地调度筛选 | 不重演拿取、不猜原状态，选择当前已验证的安静保持 |

上述放松时间不直接复用后台业务恢复的等待窗口，也不改变历史保存条件。如果连声音是否结束都不知道，由播放程序处理故障；身体仍可走兼容的放松路线，但不能自动确认回复已经完整交付。

## 13. 闲时主动搭话怎样决定、怎样撤回

“内心有想说的事”先成为WAI的发言考虑。WAI继续检查话题是否有效、是否该打扰、是否已经说过、当前是否处于安静或专注限制。

这一步通过后，还要确认内容准备好了、当前输出设备适合发声、没有另一轮回复占用播放。

人物随后可以抬眼、转向你、准备搭话。身体准备和语音生成并行，不能要求先放下所有东西、站好后才出声。

在第一点声音开始前，再看一次：你是否已经先开口、这条内容是否被撤销、当前是否仍允许主动说话。若已经不合适，撤回准备，转为倾听。

说话过程中，不能因为系统发现“她正在生成”就把她自己的这次输出取消；需要区分正在继续同一段主动讲话，还是另一个回复来争用输出。

已经说出一部分后断线，也不能假装一句没说过，整段重播。只确认能够证明已播放的部分；不知道听到了多少时，保留不确定，不自行补发全部内容。

当前最多登记浏览器确认的播放进度，这不等于扬声器实测或用户已经听到。没有可靠的文字时间对应，就只记录部分播放或进度不明，不能把整段文本记成已送达。

目前还不能把播过的音频长度准确换成说过哪些字，因此不能按比例截取文字，也不能把整段回复写成已经说完；这部分交付记录仍需补齐。

**谁判断：**WAI已有主动系统决定这件事是否值得说、现在是否适合打扰；输出程序确认实际发声资格；本地调度只安排搭话准备。内容和处境可以来自已有模型分析，重复、撤销、输入输出占用等由程序核实。

**依据是什么：**具体有效话题、是否已说过、当前安静或专注限制、是否有其它回复，以及用户是否抢先开口。在准备时与第一点声音进入播放前各核对一次，不能把较早拿到的允许当成永久许可。继续同一次讲话时，只豁免这次讲话自己造成的忙碌；新的用户输入、撤销、内容来源和有效期等限制仍持续检查，不能因为已经开始说了就一直放行。

**判断不出来怎么办：**开口前缺关键依据就取消本次准备或留待下一次正常机会，不让人物一直抬手等结果。依赖模型的处境判断超时，也不新增串行重试来拖住用户回复。已播一部分后出现故障，由原交付流程保留可证明的事实和不确定性；不按音频比例编造已说文字、不整段自动重播、不记成完整送达。新输入优先，主动内容是否以后再说仍由原主动系统决定。

## 14. 如果消息晚到、资源没加载好或页面卡住

| 问题 | 应采取的行为 |
| --- | --- |
| 某个动作尚未加载 | 继续声音和当前可靠姿态；使用已加载兼容版本或放弃该次动作 |
| 表情资源失效 | 保留可用基底和口型，不停止音频 |
| 身体转场算不出合法路径 | 用兼容版本或保持，明确记录拒绝原因 |
| 晚到的旧挥手命令 | 检查它所属的那次交流是否仍有效，过时就丢弃 |
| 页面隐藏很久后恢复 | 先核对当前音频和身体现场，不高速补演积压动作 |
| 上次在放杯子，但未确认放好 | 不猜杯子已经在桌上，按最后可信持物状态重规划 |
| 情绪暂时没有更新 | 维持或缓慢放松表情，不让全部动作和语音停住 |
| 播放状态暂时不明 | 不宣告已经说完，也不由人物擅自停止宿主管理的声音 |
| 同一条消息重复收到 | 一次要求只执行一次，不能重新计为新的动作理由 |

为了避免卡顿，常用动作提前加载；接下来可能使用的相关动作在后台准备。每帧只采样已经选中的少量轨迹，不重新遍历整个动作库，也不查询记忆或等待云模型。

身体、衣发、脸和口型最后由一个合成入口统一写入，避免几个旧控制器各写一次，后写者覆盖前面的结果。原有独立实验控制器需要改成“提供姿态结果”，不能全部同时直接控制模型。

**谁判断：**资源加载程序报告可用与失败；播放程序报告声音状态；场景记录报告物体和身体；本地调度检查来源、时机与重复。最后的统一合成入口检查哪些部位已被占用，开发时通过测试确认没有旧控制器绕过它直接覆盖；模型不负责猜文件是否加载好。

**依据是什么：**按这次交流或活动的记录核对，并比较是否已被较新的取消、输入或现场变化替代。模型没给意见、任务没有开始、资源加载失败、身体无法接入，是四种不同原因，要分别记录。每次选择留下人能读懂的一句话，例如：“未挥手，因为双手正在持书，且没有验过单手持书版本。”不能只记录“被规则拒绝”。

**判断不出来怎么办：**每种故障只限制依赖它的部分。拟采用的有限恢复办法如下，次数和时间仍需实施时验证：

| 不确定的情况 | 立即怎么办 | 什么时候结束这次等待 |
| --- | --- | --- |
| 附带手势的资源还没好 | 声音继续，保持已加载姿态；资源可后台加载 | 对应话段已过或被取消就放弃本次手势，即使后来加载成功也不补演 |
| 明确动作请求的资源暂缺 | 本轮仍有效时允许一次有上限的后台加载尝试，期间先回应 | 初版以约2秒为本次动作加载等待上限；到期记录未完成，正常资源加载可继续，但不得自行复活旧请求 |
| 播放或场景记录互相矛盾 | 向各自负责程序立即核对一次，最多再重试一次；语音继续按原语音规则处理 | 人物侧核对先以约1秒为上限；仍不明就放弃依赖它的新动作，显示可恢复故障，不伪造播完或空手 |
| 正在收势却迟迟未完成 | 停止排入新的冲突动作，尝试该动作预先验证的稳定出口 | 每个动作单独登记时限；到期标为失败，不再无限重试，保留最后可信支撑并等待明确恢复 |
| 页面很久没显示又恢复 | 丢弃已经过时的表现，重新读取当前音频、场景和活动 | 按有限核对处理，不快进补演历史；关键状态仍不明时禁用新的复杂转场 |

上述时限只界定人物这次尝试何时失败，不取消用户的业务任务、不强迫停止正常语音，也不允许将身体突然归零。若异常严重到连稳定出口都无法验证，只保留最后可信姿态并明确报告需要恢复；这属于故障，不能假称仍在自然表演。必要时由用户重新载入预览，恢复前仍不猜道具已经放好。

## 15. 如何证明方案有效，而不是只证明代码没报错

先检查规则，再看真实角色，最后才做有界云端对话。三种结果分别记录。

规则测试包括：晚到、重复、改口、先暂停后恢复、取消与新要求同时到达、原活动物体已移动。要能解释最终为什么选了这个动作、另外几个为什么被淘汰。

真实模型至少连续看这些完整过程：

1. 原生待机进入说话，结束后自然回到保持。
2. 坐着拿书被叫到，坐着交流，再继续原活动。
3. 挥手在准备、最快摆动和收回三个不同阶段被打断。
4. 举杯或转身中收到用户输入，物体、脚底和身体连续。
5. 主动搭话刚准备时用户先开口，准备能够撤回。
6. 字幕迟到、音频暂停、页面隐藏再恢复，不补演错误动作。

画面上检查：手是否瞬间反向、肩肘是否突然换位、鞋底是否滑、书是否变大或消失、头发裙摆是否独立跳动、表情是否突然清空、口型是否被开心表情盖住。

速度检查：与原语音链同条件比较首声时间、连续播放停顿；把首次资源加载和稳定运行分开。角色动作开始的耗时，不冒充模型首声耗时。

本轮提出的试调目标包括：普通注意变化争取约0.1秒内开始；空手收势先以约0.6秒内让出为目标；持物和支撑变化允许更长。它们不是强制截断时间，实际素材若做不到就换方案，不能瞬移凑数字。

自然度仍需连续观看。姿态接缝很小、数学曲线连续，都不能单独证明“像人”。最终保留你的三个要求：身体参与幅度、近身肘部、利落挥手。

**谁判断：**自动检查负责可计数的规则和运动变化；开发者核对记录、真实模型和连续视频；你可以直接从观感决定是否符合角色。自动测试或另一个模型的好评，都不能替代连续观看。

**依据是什么：**每个判断至少放一例条件齐全、一例关键依据缺失、一例旧结果迟到或被新输入推翻。检查不仅要回答“选了什么”，还要能说出“谁给了依据、为什么其它选择被排除、没结果时退到哪里”。例如：引用“挥手”不触发，情绪分析迟到不重演旧反应，播放结束但第二段未到不进入长休闲。

**判断不出来怎么办：**没有实模连续观看，就注明自然度未验；没有设备录音或回采，就只报告浏览器排程同步；没有真实对话就不报告云端全链路通过。一个组合有争议，只把该组合留在手动预览，不拖停已验证部分，也不通过缩小整体身体幅度掩盖。试调参数由对照数据和连续观感共同决定，不能把本文初值当成已经测出的最佳值。

## 16. 当前已有与仍需制作的部分

**谁判断：**开发者以当前源码接线和实际验收记录登记完成程度，独立审阅者核对；模型宣称“支持”或文件已经存在都不算做完。

**依据是什么：**分开记录“有这个零件”“已经接通”“已经运行验证”。当前状态如下：

| 环节 | 当前已经有的依据或零件 | 本方案还需要补的部分 |
| --- | --- | --- |
| 发声与轻注意 | 语音开始通知、有效或无效输入、暂停与取消流程 | 把早期注意和理解后反应统一接到人物 |
| 请求动作、解释意图 | 当前Qwen可在回复中附带一组表情动作，工具参数和归属有检查 | 请求来源、否定与引用约束、统一身体检查、未完成反馈；无可靠逐词时间 |
| 任务开始与思考消化 | 真实任务状态、后台分析、内心意图及部分有效性保护 | 哪些值得外显、怎样结束、同一原因不重复、旧意图淘汰 |
| 情绪与精力 | 事件分类、数学情绪和生活计算；当前D语音实验仍由Qwen选表情、力度固定 | 人物读取数学基调、区分生活精力与回复补偿，再与短表达组合；当前尚未统一接好 |
| 动作素材 | 原生动作表情、绑定、部分衣发适配以及独立预览 | 每种可自动使用场景的完整说明和验收，不把全部库直接放行 |
| 身体过渡与现场 | 局部手部求解、保留速度的衔接、部分显示后观测和活动实验 | 统一最终身体记录、原生全身衔接、固定握点、接触与恢复检查 |
| 表情和动作联动 | 表情配方、动作控制与局部实验 | 同一次表达统一选择和撤回，说话表情与口型隔离，单一合成入口 |
| 眨眼、视线、小动作 | 独立控制器与部分节奏限制 | 统一目标来源、真实显示记录、跨动作去重和未知处理 |
| 音频同步与口型 | 浏览器播放排程、便宜口型分析、动作工具接入 | 明确证据级别、迟到处理、全身和衣发同步；更准确口型另行验证 |
| 打断与历史 | 现有输入接纳、取消、已送达历史保护 | 所有原生动作的可靠出口、异常让出、统一旧命令拒绝；保护规则继续保留 |
| 交谈退出与活动恢复 | 输入输出事实、部分处境判断和活动记录 | 完整退出规则、分阶段放松、活动现场核对，不等待后台分析才放松 |
| 主动搭话 | 主动内容与准入业务逻辑 | 接到当前双工语音的准备撤回、首声复核及部分交付处理 |
| 故障与验收 | 各实验的局部检查和历史证据 | 全链路有限恢复、可读选择原因、新旧对照；本文新增规则尚未运行验收 |

**判断不出来怎么办：**没有完整证据的项目标为“待接入”或“未验收”，不拿相邻实验代替。正式语音和已验证动作继续使用；新组合先留在独立预览，查清失败原因后再开放自动使用。

本次只补方案与核对判断来源，没有修改运行程序、重测轨迹或调用云模型。文中的源轨迹数字和资源结论来自此前检查；它们不能证明新增调度已经运行。没有为这八类判断增加八次模型调用，也没有把后台解析移到快速首声之前。

后续实施记录应能用一段人话回放一次选择，例如：“你说不要挥手；Qwen理解为撤销；语音链确认本轮有效；本地发现右手仍在向外摆，于是取消后续挥动并沿已验证路线收回；新回复正常出声。”或者：“你要求挥手，但持书版本未验证，因此没有执行，也没有记成已完成。”
