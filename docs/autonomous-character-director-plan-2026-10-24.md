# 人物调度中心：实施计划与验收标准

日期：2026-10-24。状态：**实施计划，完整自主中枢尚未编写。** 本次程序改动仅处理用户禁用的抬手 Stand2；本文列出的后续能力不能当作已经接入。

目标是：你不说话时，她能根据真实后台活动、已有内在倾向、数学情绪和现场条件，决定继续做事、休息或安静陪伴；你开口时自然转向交流；交谈结束后决定恢复、换一件事或保持；有真正想说的内容时，经现有主动交流许可再搭话。每次决定都能解释原因，身体、脸和声音有共同的交流目的。

本计划接续原有[工程说明](unified-character-director-engineering-2026-10-23.md)及[接入准备](character-director-integration-readiness-2026-10-23.md)。若旧说明与本计划对 Stand2、当前完成程度、实施顺序的说法不一致，以本计划为准；旧实验和测量保留原样。

## 1. 先把现状说准确

| 目前实际有什么 | 可以复用什么 | 还不能据此宣称什么 |
| --- | --- | --- |
| 原生身体、衣发、表情和注视资源，以及人工检查工具 | 已有轨迹、重定向、配套衣发和表情执行 | 文件可播不等于适合自动使用；名字不证明用途 |
| 原生动作播放器 | 起势、循环、结束；从当前姿态和速度接续；部分阶段保存与恢复 | 任意动作互接、任意碰撞、任意支撑都已解决 |
| 活动与取放物实验 | 已检查过的特定桌椅、持物、拿放及活动衔接 | 可以把实验里的所有场景条件直接套到其它场景 |
| 闲时 demo | 真实导入 WAI ActivityPlanner / LifeThreads；隔离的本地资料索引工作；暂停、恢复、真实产物 | 正式 V2 后台全部接入、数学情绪接入、自主选择任务或动作 |
| 当前 demo 的动作选择 | 固定状态映射，开始工作用 Thinking01，其余回自然站姿 | 根据内心、情绪、场景、动作库自主选择 |
| 页面“播放完整流程” | 自动发出开始、暂停、继续、模拟开口等测试事件 | 人物自己产生了这些事件或决定了整段流程 |
| 已有语音实验 | 流式音频、字幕、工具动作、取消和交付保护的已有实现 | 本页有真实回复语音，或原有多个导演已经统一 |

实现目标是补上真正的选择与仲裁层，接通事实来源，然后逐组开放已验证资源。不会把现有一键演示改个名字当成新中枢。

### 截图中的动作从此禁用

用户禁止的是持续抬起一只手的原生 **Stand2**：组 `native:8b2e802a90db3da3`，片段 `body-stand2-84d0c0a158`，来源 `Aimisi/CommonAnim/Stand2.uasset`。

本次将当前 demo 的默认站姿改为原生 **Stand01**，并在 `preview/core/character-motion-policy.js` 记录明确禁用规则。当前 demo 的初始化和每次换段都检查；以后中枢的候选、实际提交、恢复和兜底必须共用这条规则。改名、镜像、变速仍须保留原来源，不得绕过禁用。

旧素材和旧验收录像留作档案，旧资源浏览页的人工查看不代表自动许可。相似名字如 Team_Stand2 不凭名字自动判为同一动作，也不因此自动开放。新遇到视觉上相同的衍生动作，补登记同一禁用原因。

这项偏好不会降低其他动作的身体幅度，不修改近身肘部、利落挥手和现有衣发绑定。今后用户在某个正在执行的动作上说“不要这个”，记录实际来源与场景；取消尚未执行的部分，从当前姿态完成必要收势，再保存禁用项。持物和支撑不能靠瞬间清零解决。

## 2. 谁负责什么，最终听谁的

统一中心负责人物表现的决定和发令。它不重做记忆系统、情绪系统、后台生活系统，也不代替回复模型回答。

| 要决定的事 | 最终负责方 | 中枢能做什么 | 来源不够时怎么办 |
| --- | --- | --- | --- |
| 用户是否正在说、回复是否已取消 | 现有对话与语音运行时；浏览器声音起点可先要求注意 | 立即停止安排新的闲时表达，撤销该轮旧动作 | 只作注意反应，不根据声音认定听懂或同意 |
| 后台任务开始、暂停、恢复、完成 | WAI 的实际任务执行与活动记录 | 申请变化，等执行方接纳；读取事实安排表现 | 不把动画结束记为任务完成，不自己编工作进度 |
| 当前情绪和生活精力 | 现有数学情绪与真实生活状态 | 只读，调节允许的表情与动作倾向 | 不凭语气另造心情；缺值不新增强烈情绪表达，保留可靠基调 |
| 某句话在解释、拒绝、请求挥手 | 回复模型的有效工具意图，或已有语义分析 | 作为有来源的建议，检查当前语境与身体可执行性 | 不明确就保持交流姿态，不默认展手或点头 |
| 有什么内在关注 | 现有 inner frame 等后台状态 | 作为弱倾向，帮助在同样可行的选项间取舍 | 不把一段自述当事实、工具权限或必须行动的命令 |
| 现场有无椅子、手里有什么 | 实际场景和道具控制器 | 读取物体、握持、支撑与位置，筛掉不满足条件的动作 | 未知不当作空手或空场；仅限制依赖这些条件的动作 |
| 哪些动作适合当前模型和用途 | 资源准备与实际模型验收记录 | 按明确适用条件使用 | 没有通过的组合继续留在人工预览 |
| 本帧身体和脸实际写成什么 | 唯一的角色合成与播放入口 | 合并身体、注视、眉眼、口型、衣发 | 其它实验导演只能提交建议，不能再直接抢写骨骼 |
| 要不要主动说话 | WAI 现有主动输出许可与语音交付层 | 提供表现准备，接纳批准后的输出 | 没有有效许可就不出声；不能因转向用户而默认批准 |

初版把表现决策放在本地角色侧，便于及时读真实姿态并反应；WAI 发送小型事实快照和事件。后台任务状态仍由 WAI 管。这样不会出现前端和后端各自决定一遍身体动作。将来换部署位置，也保持相同的权责。

**精力要特别区分。** 当前 `runtime_soul()` 为了允许直接回复，会临时把睡眠改为可回答，并抬高精力下限。闲时活动必须读取这一步之前的真实生活睡眠与精力。回应用户的临时许可，不意味着角色可以持续做活跃闲时动作。

## 3. 中枢收到的信息必须能核对新旧

每条信息至少说明：谁发的、属于哪次会话或哪项活动、这一代任务的编号、更新顺序、发生时间、有效条件、被什么事件撤销。动作也保留这些依赖。不是把几个最新字符串拼起来就开始动。

- 对话层报告说话、等待、播放、取消、结束。一次停顿不等于交谈结束。浏览器断开也不能自动表示用户离开。
- 后台报告实际阶段，并区分“排进计划”“执行器已经开始”“成果已经保存”“活动正式结束”。网络请求等待和真正处理资料分别标明；普通缓存维护、向量写入、日志整理默认不需要身体表演。
- 情绪报告当前数学状态及其更新版本。生活系统报告真实睡眠和精力。中枢可以平滑视觉输出，但不反向改情绪值。
- 身体报告最终合成姿态、速度、支撑脚、坐姿支撑、手的占用和正在执行的退出过程。读取实际已经显示的状态，不能只读上一次发出的目标。
- 场景报告物体身份、位置、接触位置和场景版本。用户位置没有追踪能力时，使用明确配置的交流方向，并标明是默认方向。
- 资源与偏好报告当前许可版本、模型/绑定版本及禁用记录。换模型或改衣发后，相关旧验收不能无条件沿用。

准备动作后、实际播放前再核对依赖：例如“手空着”在选择时成立，提交前拿起了书，就拒绝那个空手手势。只比较这个动作依赖的版本，不能因为无关日志增加就让全部动作反复重算。

断线恢复先获取完整当前状态，再接新事件。晚到的取消只能取消它自己的那一轮；旧任务的完成也不能结束新任务。缺少编号或来源的外来动作不执行。日志只保存决定所需的短原因与来源引用，避免把私人记忆正文送进浏览器诊断。

## 4. 哪些事件会让她重新考虑动作

不是每帧重新选动作。正常每帧只采样和合成现有轨迹；下列事实改变时才重新考虑：

| 发生的事 | 由谁判断、依据 | 允许产生什么选择 | 判断不清时 |
| --- | --- | --- | --- |
| 你开始说话 | 语音运行时的有效开口事件；本地检测先请求注意 | 面向交流方向、结束闲时表达、保留必要收势 | 不产生赞同、否定或“听懂了”的点头 |
| 你明确要求挥手 | 有上下文的语义结果；识别否定、引用、假设和要求对象 | 当前姿态下可用的招呼动作 | “不要挥手”是禁令；不清楚则不挥手，必要时由回复模型问清 |
| 她正在解释 | 当前回复的有效交流意图及已生成的字幕内容 | 保持注视、轻量强调、少量已批准解释动作 | “解释”不自动要求摊手；没有合适时机就只说话 |
| 后台真正开始一项生活工作 | 执行器开始记录与任务类型、材料引用 | 对应专注或阅读表现，或继续原有安静姿态 | 只有计划、没有开始回执，不摆出正在工作的姿态 |
| 有一个尚未结束的内在关注 | 现有 inner frame 的有效来源、持续时间和关联事件 | 给继续当前活动、稍作整理或保持增加一点倾向 | 不因文字里出现“思考”就必做托腮；来源过期直接不用 |
| 数学情绪确实变化 | 有效状态更新，幅度与持续性均达到待标定条件 | 平滑改变眉眼、姿态倾向和后续选择 | 一帧噪声不触发表演；不知道原因也不编成“突然伤心” |
| 实际精力变低 | 生活系统的真实数值和醒睡状态 | 减少主动大动作，允许经验证的休息方式 | 不靠一句“我累了”直接落座；没有椅子就不坐 |
| 当前阶段到达可退出位置 | 播放器实际阶段、脚和物体的状态 | 完成已选退出，或检查是否仍需继续 | 到时不等于支撑成立，超时走失败处理 |
| 交谈告一段落 | 对话运行时明确结束；没有回复在途、待播放或明确等你回答 | 重新检查原活动、生活安排与环境 | 没有结束事实就保持交流可用，身体可放松但不擅自走开 |
| 有可分享的真实成果 | WAI 成果与主动话题系统 | 送入既有主动输出许可流程 | 没有成果或已撤销，不作完成庆祝或主动播报 |

允许一个低频检查确认状态是否过期、执行是否卡住。它不是“每隔十秒随机做点什么”的触发器。具体检查频率由实测事件量和开销确定，不能拿检查次数当行为数量。

## 5. 候选到底从哪来

先列“当前有理由做的事”，再找“能表达这件事的动作”。候选是一个有来由、能执行、能退出的完整选择，不能只是一条动画编号。

固定有五个入口：

1. **继续当前行为。** 它总是被重新检查，不是永远合法。活动仍有效、姿势仍成立、没有更紧迫需求，继续原来的阅读或安静站立通常优于换动作。
2. **对当前事件作必要反应。** 例如你开口产生注意与让出；你请求挥手产生招呼；不会从整个库随便抽一个好看的动作。
3. **已经批准的生活任务。** 已开始的工作提供表现选择；尚未开始的可用任务只产生“申请开始”的选择，WAI 接纳并确实执行之后才进入工作表现。
4. **允许的休闲与小调整。** 必须有具体条件，如长时间同一姿势且接近已检查姿态范围、低精力且有可用座位。休闲读书与实际处理数字资料分别标记，前者不能生成完成资料任务的记录。
5. **有效内在倾向。** 只改变前四类中兼容选项的偏好，或者向生活系统提交待批准的兴趣建议；不能越过任务许可、生成道具或触发外部工作。

每个选择携带以下说明：这次为什么出现、使用哪条当前事实、打算达到什么结果、适用姿势和物体条件、参与哪些部位、预计持续到哪个事实、如何退出、何时失效、过去是否做过、采用哪个已验收动作组合。

动作查找按用途索引：招呼只查允许的招呼组，持书倾听只查持书可用版本；一开始就不把攻击、用户禁用、未批准语义、缺资源的动作放进去。先找符合用途的原生版本，再查已验证的已有原创版本。没有符合条件的资源，保留“保持/只注视/暂缓”，不能因为库里没有就现场拼一个大动作。

**例子：她站着整理资料，你开口了。** 可考虑的是停止新工作表达、原生收势、转移注视、自然站姿倾听。正在思考的循环因为交流已占用而不能继续；Stand2 因用户禁用直接剔除；坐下因无座位和无必要性剔除；挥手因你只是开口、没发生招呼语义而不产生。最终并非在一堆随机动作里“智能挑选”。

## 6. 筛选顺序与最后怎样选择

先过必须满足的条件，再比较好坏。以下任一条失败，不能靠“情绪很匹配”加分补回来：

1. 用户禁用与明确边界是否允许；禁止动作连恢复与备用方案都不能用。
2. 来源是否仍真实、同一代、未撤销；不能引用已纠正或取消的事件。
3. 当前交流是否允许分心或主动发声；等待你回答时不擅自开始一段长闲时活动。
4. 动作在当前模型与用途下是否已经批准；所有文件、配套衣发和必要表情是否可用。
5. 当前站坐、支撑、手脚占用、道具和空间是否满足；未知按依赖缺失处理。
6. 从当前姿态到起点、从动作中途到退出，是否都有已验证路线；只有主体片段不够。
7. 说话所需动作是否还能赶上对应内容；已经说过去的内容不补演。
8. 是否违反重复限制、活动持续性或动作密度；它是否真的比保持更有必要。

通过后按容易解释的顺序比较：先处理必须让出的交流与撤销，再满足明确用户请求，再考虑有效任务的延续，然后比较同等用途下的切换代价、当前情绪精力是否相容、最近是否重复、是否更容易退出。新颖性只在同样合理的选择间起作用，不能成为换动作的主要理由。

首版不用一堆未经校准的浮点权重冒充精确判断。采用分级比较，并记下每次淘汰的原因。比如两个专注动作都能用，当前动作还成立且换另一个需要抬手重新准备，就继续当前动作。确实需要评分时，再根据人工标注样例标定，报告权重与误选例子。

避免抖动有三层：同一来源重复事件合并；当前行为没失效时享有延续优先；普通替换在当前可退出位置发生。明确打断和撤销不受普通最短停留时间限制。重复统计从实际开始显示时计数，排队后被取消不算做过；变速或镜像的同源动作仍算重复。

最后可以得到四种结果：**现在开始、继续当前、等条件成立再检查、放弃此次表达。** 等待有具体原因和截止点：等收手、等资源、等词句时机都不同。事件已经过期或条件明确无法成立，就放弃，不能无限留在队列。

## 7. 动作说明准备到什么程度才能开工

不必把所有资源写完才开始。先选择一小组真正能形成完整过程的资源，但这组不能只验主体：自然站姿、专注起势/循环/结束、注意转移、可用的招呼、拒绝/确认所需的小反应及眉眼。站姿空手先贯通，其它场景暂不自动开放。

同一动作族共用一张说明，片段登记阶段差异，配套衣发和脸部引用资源记录，避免为每个文件重复写长文。说明要包含：

- 用途、允许触发与明确禁用语境；不把“好看”“自然”当用途。
- 起点和终点的站坐、朝向、支撑脚、双手占用、道具关系和允许偏差。
- 哪些骨骼与脸部通道在动，是否改变重心、根位置、朝向；有没有脚的动作。
- 起势、主体、循环、退出的位置；各阶段如何被打断，何时必须先完成支撑动作。
- 所需原生衣发与脸部组合，以及说话时必须让给口型的通道。
- 可以直接衔接的动作、需经过的中间步骤、失败后可停在哪里。
- 实际模型、绑定、源文件版本、已测入口与中断点、人工观看结果。

时长、轨迹、部位变化、循环接缝可用程序提取；用途、自然观感及场景适配需要真实画面确认；脚锁、拿放和退出路线是执行能力，不能靠写一句“可打断”就得到。每组经过资料核对、真实模型运行和人工观感后才开放。被用户否决的组从许可中撤出，不删除历史证据。

## 8. 从一个动作到另一个动作，实际怎么走

先问“能否直接接”，再决定怎样插值。直接接至少要求支撑和道具关系兼容，起点在已测范围，参与部位没有被别的动作占用，有可执行退出。都是站姿并不足够：一个人在迈步、另一个双脚固定，也不能随便混。

**可以直接接时：**播放器取当前已经显示的每个关节位置、朝向和运动速度；把下一段放到当前合理的世界位置与朝向；用保留初速度的短过渡接入原轨迹。过渡时长按距离、速度和已验收范围选，不能把所有动作固定拖慢。身体主体、利落挥手节奏和幅度仍保持原样。四元数旋转与残差衰减只是实现手段，不是防穿模保证。

**不能直接接时：**中枢查预先验收的小范围衔接路线。首版只走直接接或明确列出的短路线，不让语言模型现场发明运动路径。每条路线注明前置事实、执行步骤、结束事实、取消方式和失败保持姿势；上一段的实际回执允许下一段开始。

| 当前情况和目标 | 实际过程 | 谁证明完成 | 缺能力时怎么做 |
| --- | --- | --- | --- |
| 双手持书 → 倾听 | 先转移可用的眼神和头部；继续可靠持书；必要时完成当前翻页 | 道具握持与播放器接触状态 | 没有持书转头版就保持持书，只作兼容眉眼，不强迫放书 |
| 双手持书 → 双手摊开 | 确认真实可放位置；走已验证放书路线；物体支撑稳定后释放双手；重新检查展手是否仍需要 | 道具控制器确认落点、支撑与解绑；不是计时结束 | 无处放书则选不占双手的表达；不让书消失 |
| 正在落座 → 回应用户 | 先接纳交流与注意；身体完成必要落座；在坐姿支撑确认后接倾听 | 椅子、骨盆与脚支撑检查 | 不停在半空；不因开口要求起身 |
| 坐着 → 站姿招呼 | 先查坐姿招呼；确需站起才释放必要持物、完成起身与落脚，再招呼 | 对应活动执行器及场景检查 | 起身路线未经验证，就使用坐姿兼容反应或仅口头回应 |
| 转身中 → 看向用户 | 保留当前转动和落脚，走到已标注可停阶段，再调整朝向 | 实际根运动与支撑脚 | 不直接把整个模型旋转到正面；未知支撑时不接新的移动 |
| 手在脸边 → 收回 | 从当前速度进入经过检查的近身退出；避开袖口、长发；保持身体参与 | 真实模型轨迹、净空与当前阶段回执 | 没有合格退出就不把该动作开放自动调用 |

同一部位一次只归一个执行者。眼神可以在手臂收势时先回应，但不能把任意完整原生动作裁成“只有上身”使用；裁切后要重新验收脚、重心与衣发。过渡期间头发和裙摆使用同一采样时钟与匹配的组合方式，不再把已经烘焙的完整姿态叠加一次。

一条路线如果超出“原阶段剩余时长 + 已测过渡余量”仍没收到完成回执，视为卡住：停止发后续步骤，保留可靠持物与支撑，报告失败。只重试能够证明可重复且未改变场景的步骤一次；其余重新检查当前事实。不能靠超时直接假定书已放好、脚已落地。

## 9. 你不说话时，完整流程怎样发生

中枢同时维护三件独立的事：后台实际在干什么、身体正在做什么、是否仍处在与你交流的过程中。不能用一个“忙/闲”把三者混在一起。

**没有活动时。** 先确认交流确实允许闲时行为，再看 WAI 是否有可执行任务。没有任务，安静站立或保持当前坐姿就是合法结果。已有内在关注可以影响她留意什么，但不会凭空生成一本书或必须表演的思考。符合姿势、精力和场景条件的小调整可以参加选择；没有必要就不动。

**开始活动时。** 如果后台已经真正开始，中枢选择与任务相符的表现；如果只有待开始任务，中枢向原执行系统申请，收到“已执行”事实才进入工作表现。先确认起点和退出路线，进入起势，再由实际阶段回执进入循环。场景缺书不妨碍后台整理数字资料，但不安排翻书；普通数据维护默认连专注动作也不触发。

**持续活动时。** 正在读资料不需要每条进度都换动作。维持同一活动，动作循环采用经过检查的同族变化；允许在自然阶段小幅调整注视和舒适姿势。进度变化只在交流意义改变时影响表现，例如从阅读转入已经保存的结果检查。任务在等待网络时可以放松，但不能凭计时装成完成。

**暂停时。** 中枢马上停止追加不必要的活动表达，同时通知后台活动管理器。后台按现有能力停在可保存的位置；正在进行的不可撤销操作按原系统结算，不由动画强杀。保存两份不同进度：业务处理到哪里；身体处于哪段、哪一时刻、持有什么、如何退出。身体通常完成必要收势并面向交流，不是把所有骨骼冻住。

**恢复时。** 必须重新确认交流结束、任务仍存在且未撤销、后台许可恢复、资料仍有效、场景和身体仍适合。业务确认恢复后再安排相应表现。原身体阶段仍兼容，就从保存点接续；已经换了座位或放下了物体，则从当前事实走新路线，不能硬跳回旧姿态。原动作被新禁用，原任务可继续，但表现要换合法版本或保持。

**完成时。** 后台真实产物与完成记录决定工作完成。中枢结束相关循环，完成收势，重新考虑安静陪伴或下一项已获许可的活动。成果可能值得分享，也可能不值得；不默认笑、挥手、播报。实际成果完成但计划窗口还没结束时，不能继续声称正在处理已经做完的工作。

**失败或取消时。** 业务按原系统记录原因；表现从当前状态退出，不播放成功姿态。旧任务的迟到进度不再带动身体。任务被用户取消后不得自动恢复，即使之前保存了动作检查点。

当前原活动计划有 600 秒安静条件等实际规则。现有 demo 用 120 倍隔离时钟展示，不代表正式系统只等 5 秒。接真实活动时保留原规则；生活活动尚未允许恢复期间，人物可以自然站立、注视或作已允许的小调整，不必僵站，也不必偷偷提前恢复工作。

## 10. 你开口、交谈和离开时怎么交接

用户开口触发两条同步但不互相等待的路径：语音层按现有打断策略处理播放与回复；人物侧立刻撤销旧表达并把可用注意转向用户。身体收手、落脚或落座可以继续，语音不用等它完成。收到声音不等于批准打断所有云端响应，最终语音取消仍由原运行时决定。

交谈中区分：你在说、她在等回复、她在实际播放回答、她在等你接话。各状态都允许自然保持；等待首包不意味着一定“疑惑”或“苦想”，也不为掩盖网络延迟频繁托腮。收到有明确语义的回复意图，才安排相应表达。

“听见了”与“同意你”分开。音量起点可引起注视；赞同点头要有语义依据。要求动作的句子必须结合上下文，避免把“她刚才说不要挥手”当成用户正在要求挥手。识别结果有冲突时，明确否定和取消先阻止新动作；不能因为模型自报高置信度就忽略语境。

交谈结束也分两步：先确认没有等待中的回答、未播放音频和待用户接续的要求；再重新检查后台恢复条件。仅仅几秒没说话，最多允许身体放松，不能让她走开。明确“你先忙”可以由语义层提出结束交流，但真正关闭会话和允许任务恢复仍要得到现有运行时的接纳。

刚恢复活动你又开口，就重新执行让出过程。新一次交流有新的归属；上一轮晚到的表情、工具命令、字幕和音频不能复活。连续打断时优先保持易接话的姿态，避免反复演完整起势和收势。

## 11. 从休闲到主动搭话，需要四次不同检查

1. **确有可说的内容。** WAI 的真实成果、承诺、已批准话题或其它现有来源提出候选。人物端不能因为太久没动就编一个话题。
2. **现有主动规则允许。** 原系统检查隐私、来源撤销、用户忙碌/睡眠、频率和当前交互状态。动作系统不复制一套较宽松规则。内在倾向可以使某个合法话题更值得考虑，不能直接批准出声。
3. **即将播放时仍允许。** 生成过程中用户可能已开口或话题已失效；首个音频真正排进播放前复查。身体可以先从休闲转为交流可用，但不通过强烈招手制造“已决定打扰”的承诺。
4. **只记录实际交付。** 播放到哪里、是否中断，由原语音交付记录决定。没有播出的文字不写成已告诉用户；动作完成也不算说完。被打断的同一内容不能立刻再主动重播。

主动回复开始后，系统会自然出现“自己正在生成/播放”的状态。继续权限要识别这正是当前已批准的输出，不能把自己的忙状态当成第三方竞争而不停自我取消；新用户事件和撤销仍能终止它。

当前独立 demo 不具备这条真实主动语音通路。实施时必须单独接原主动许可与现有语音入口，单独验收；只做出转头或说话姿态，不能宣称休闲到主动搭话已经完整接通。

## 12. 表情、身体、眼神和嘴怎样联动

每次表达使用一个共同的“这次在回应什么”的记录。例如“用户开口，注意转向交流”：眼神可以先到，眉眼从工作专注回到倾听，手臂走既定收势，身体保留支撑。它们不必同一帧同时开始，但都依赖同一个事件，取消也能一起找到。

脸分三层：已有数学情绪给持续基调；当前交流作用给短暂表达；眨眼与口型负责生理和发音。某次任务成功不直接把情绪改成高兴，模型工具给出的“开心”也只作为待检查的表达建议，不覆盖数学系统。

优先选已检查的游戏表情，缺少合适用途再用现有原创配方。原生静态脸提供形状，进入、保持、退出仍需时间控制。保留左右差异及已确认的有符号权重；不能一律压成 0 到 1。资源是否适合当前语义必须单独确认，“惊讶脸能播”不说明适合所有疑问。

说话时发音嘴形由口型层拥有，表情不得把它盖住。眉眼、嘴角若与发音有共享通道，按已建立的叶形变归属裁切或降级，不能两边最后写入者获胜。所有脸层最终只合成一次；身体、注视、衣发同理。

注视从实际目标或配置方向获得，按眼睛、头、胸能承受的范围逐步转移。没有位置追踪就不宣称看向真人眼睛。眨眼和小幅调整要遵守当前注意与动作阶段，不让每个模块同时运行自己的周期摆动；随机只可在已批准的微小变体中打破机械重复，不能随机产生交流含义。

表情动作联动验收既看共同事件与取消，也看真实形变和身体画面。数字里眉毛变了但脸看不出来，仍不算完成；情绪不匹配时，宁可保留中性兼容表达，也不强做笑脸。

## 13. 如何不拖慢语音，并保持动作时机

语音采集、检索、生成和播放继续走已有链路。动作中枢拿事件和必要摘要，在旁路工作；音频转发不等待挑动作、载入游戏资源、语义分析或写日志。模型不会每帧参与决策，也不为眨眼新增调用。

初版优先复用现有 Qwen 工具意图和已有后台语义结果；字幕可提供有来源的有限判断。明确请求、否定、引用等需要上下文，简单关键词只能用在已限定的明确情形，不能兜底所有语义。确实缺判断能力时先记录误选样例，再决定是否增加专用观察模型；新增模型、资源和费用另作明确实验，不悄悄成为语音依赖。

时间分开使用：

- **发言中的强调**跟实际音频播放位置走。网络到达时间和字幕生成时间只是线索，不是用户听到的时间。没有词级对齐就标明只有片段级，不能声称精准重音同步。
- **闲时、注视、打断收势**跟本地单调时间走。音频暂停不能把收手冻在脸旁。
- **后台工作和日程**按后台时间与真实进度走，不随帧率或媒体播放加速。

动作来迟时先问“现在还表达同一件事吗”。内容已过就丢弃瞬时动作，仍有效的持续态度可继续；不会为了等手势推迟语音，也不会补演过去的挥手。动作资源预加载只覆盖当前可能使用的小组；取资源、解析和日志搬出播放关键路径，并测 CPU/GPU/网络竞争，不把异步语法当作零开销证明。

取消检查在内存里核对有效归属和撤销版本，撤销事件推动更新；不在每帧、每音频块读盘或拿后台任务的大锁。业务记忆纠正、预算、历史和已播回执仍沿原保护路径，表现层无权绕过或代写。

## 14. 缺信息、断线、卡住时具体怎么处理

| 问题 | 立即做什么 | 还能继续什么 | 恢复条件与边界 |
| --- | --- | --- | --- |
| 情绪暂未更新 | 不新增依赖情绪变化的强表情 | 已可靠的短时基调、口型、注视、当前动作 | 超过该数据源约定有效期后逐步回中性表现；不能改写数学情绪；有效期实测标定 |
| 语义分析超时或相互矛盾 | 放弃这次强手势，不堆积旧建议 | 音频回答和中性倾听 | 只有仍有效的新意图可重新参加选择，不补过去的反应 |
| 资源没载入 | 不提交该动作；不临时替换成 Stand2 | 当前有效动作或已验证自然保持 | 一次有限重试；超过当前事件时机放弃，持续活动等下一次真实检查 |
| 后台状态断开 | 停止批准新生活动作，不假装工作进度前进 | 已确认的安全收势与交流显示；语音按自己的连线状态运行 | 取得完整当前快照及新代次后再选，不重播断线期间事件 |
| 场景或持物未知 | 禁止依赖空手、座位或移动的新行为 | 当前可靠握持和支撑、相容眉眼与声音 | 实际场景重新确认；不靠随机等待认为问题消失 |
| 用户纠正记忆或撤回任务 | 立即使依赖该来源的待执行意图失效 | 无关动作、必要收势与本轮合法回复 | 使用纠正后的版本重新判断；不恢复旧检查点对应的被撤销任务 |
| 页面掉帧或切后台 | 不一次补播大量动作；限制时间步长和追帧工作 | 可用的最终姿态与必要退出 | 回前台获取当前交流/播放状态，丢掉错过的瞬时表演 |
| 播放器迟迟不回完成 | 停止派发依赖它的下一步 | 已确认接触与支撑 | 到该段已测截止时间记录故障；重新核对现状，一次可证明安全的恢复尝试后降级 |
| 重复事件、多个页面同时控制 | 同一事件去重，只给当前控制实例写入权 | 其它页面可读或作独立隔离预览 | 控制实例失效后重新获取权属，旧实例事件不能抢回来 |

“回自然站姿”只适用于站姿空手且路线成立。持书坐着的失败保持就是持书坐着；不能把 Stand01 当全场景逃生按钮。所有降级都继续遵守用户禁用项。

以下是建议的代码分工，**尚未创建这些新中枢模块**。名称用于实施定位，不要求用户理解接口字段。

| 工作块 | 负责的实际过程 | 拟放置位置与现有复用 | 完成证据 |

旧 `IdleScheduler` 的固定映射不继续扩成巨型条件表；它保留作基线实验。原生播放器不负责猜用户意图；资源册不直接写骨骼；场景控制器不宣布后台工作完成。迁移时先停掉旧导演的写入，再交给新中心，不能让新旧两套叠着运行。

## 16. 分阶段实施，什么算这一阶段交付

每阶段开始前核对双方文件认领与当前分支。先完成一个小范围端到端，再扩展动作种类。每批保留独立开关、证据和可回退入口；回退目标同样禁用 Stand2。

| 阶段 | 具体要交付的东西 | 进入下一阶段的条件 | 这时仍不能声称什么 |
| --- | --- | --- | --- |
| 0：偏好与范围冻结，本次 | 禁用截图动作、替代自然站姿、写清本计划 | 当前 demo 各回落路径无禁用动作；计划可逐项实施 | 自主中枢已经实现 |
| 1：事实与许可准备 | 少量可用动作族、退出路线、权威事件桥、数学情绪/生活精力真实来源、失效规则 | 可以拿真实事件运行“只解释不动作”的决策记录；不改变业务结果 | 只有事件表就算自然调度完成 |
| 2：站姿空手的自主闲时闭环 | 真实活动开始/保持/暂停/恢复/完成/取消；开口让出；结束后重新判断；面身同因；安静保持 | 关闭一键流程仍能对实际任务和用户事件正确选择；不同条件结果不同且可解释 | 持物、坐姿、真实回复语音和主动搭话全覆盖 |
| 3：坐姿、道具与连续路线 | 逐组开放当前已处理活动，复用明确支撑、拿放、持物倾听及中断路线 | 场景匹配、入口和退出均验证；缺物正确拒绝；人工看过连续效果 | 任何动作都可互接、任何位置都不会穿插 |
| 4：真实双工交谈 | 接现有 Qwen 意图、流式音频、播放游标、取消；表情和口型所有权统一；交流结束再恢复 | 有真实语音对照，延迟、同步、连续播放、历史和纠正保护全部检查 | 只做被动回复就包含主动搭话 |
| 5：主动搭话与长时间运行 | 接四次主动许可、实际交付回执、失败恢复与长时间行为预算 | 真正成果触发合法分享，用户忙时不出声，生成期间开口可撤回，历史无虚构交付 | 单次漂亮演示代表长期自然度 |

阶段 1 的材料语义和事件桥可并行准备，但阶段 2 开放前必须都有证据。阶段 3 与阶段 4 可按不重叠模块安排，但最终要合并检查“持物时真实交谈与打断”。阶段 5 依赖真实语音和主动许可接通，不能省略后仍叫完整中枢。

当前 demo 用模拟声音或按钮的流程可以继续作为反例回归，正式新演示应明确标识：隔离真实后台任务、录制事件回放、合成音频、物理麦克风、真实云端回复分别是哪一种。云测试使用新的明确有界批次，保留此前未知用量保护；本文不是一次云端调用授权。

## 17. 怎样证明它确实在自主调度

验收不以“按脚本演完一遍”结束。使用同一个中枢，改变真实条件，检查它自己是否作出对应选择。场景脚本只注入外部事实，不能直接告诉它下一段该播哪条动画。

| 验收情境 | 应该发生的事 | 必须留下的证据 |
| --- | --- | --- |
| 没有任务，没有你说话，也没有有效需求 | 能安静保持；不会为了展示库而随机表演 | 持续决策日志中的保持原因和实际动作数量 |
| 有合法后台工作 / 只有尚未执行计划 | 前者可选择工作表现；后者等待真实开始 | 相同输入除执行事实外不变的成对记录 |
| 有效内在关注 / 已过期内在关注 | 只对合法选项施加有限倾向；过期来源不起作用 | 来源版本、候选差异和最终选择 |
| 数学情绪相同，但你在说话 / 已结束交谈 | 交流中倾听；结束后才重新考虑闲时行为 | 证明情绪没有盖过交互条件 |
| 相同活动，精力高低或座位有无不同 | 选择相容版本、保持或拒绝；不编造椅子 | 场景与真实精力输入、拒绝原因 |
| 任何时刻要求被禁用动作 | 不播放，也不作为失败兜底 | 原编号、改名来源、恢复路径和回退路径反例 |
| 起势、主体、收势、拿放过程被打断 | 撤销旧意图，保留当前速度与支撑，交流不等身体收完 | 真实模型逐帧轨迹、脚/物体接触、正侧面连续录像 |
| 两次开口夹着短暂停声 | 保持同一交流占用，不来回恢复工作 | 语音/交互事件及恢复请求记录 |
| 动作已进入队列但尚未显示就被取消 | 不增加“已做过”计数，不写成已交付 | 队列、开始、完成、取消分开的回执 |
| 记忆纠正、任务撤销后旧结果到达 | 旧建议不能触发动作或恢复任务 | 纠正前后依赖版本和迟到包拒绝 |
| 原生动作能播但缺退出或语义验收 | 不进入自动选择 | 资源批准范围与拒绝记录 |
| 主动音频生成中你先开口 | 按原许可撤销旧主动输出；不抢回话题 | 音频实际播放位置、撤销和历史记录 |
| 后台断线、加载失败、低帧率或多页面 | 合法保持与有限恢复；无突然重播 | 故障注入、当前权属、恢复后的实际状态 |

每次记录应能用人话读出来，例如：“继续整理：任务仍有效，用户已结束交谈；恢复原片段可行。没有选择坐下：现场无座位。没有选择挥手：没有招呼意图。没有选择 Stand2：用户禁用。”不能只给总分 0.83。

测试分层：决策规则用假事件做确定性回归；真实 WAI 临时数据验证生命周期和纠正；真实 PMX 验证骨骼、形变、衣发与衔接；浏览器与物理麦克风验证实际时序；最后才用有界云调用看真实双工。每层单独给结论，不能相互替代。

自然观感要给用户连续看正面、侧面与脸部，重点看过渡、停顿和重复，而不是只挑最好的一个姿势。至少安排安静保持、任务工作、频繁打断、较长交谈和主动输出五类观察。长时间测试的时长在该阶段固定，先做半小时量级试跑，再按暴露的问题决定是否增加；这是拟定验收，不是已通过的结果。

## 18. 性能怎样测，哪些指标不能混

记录六个独立时间：事件被源系统确认、中枢收到、决定完成、执行器接纳、首个实际变化帧、退出或回归稳定姿态。语音另记首音频到达与实际开始播放；不把 CPU 提交耗时当作 GPU 完成，更不当作物理扬声器延迟。

首版设计目标是：本地关键开口事件到下一次调度机会之间不加入人为等待，声音主链路不等待中枢；加载完成后的决策以毫秒量级为目标。具体 P50/P95/P99 指标先测同机基线再固定，不能预先把旧实验数字作为新中心的保证。

比较开/关中枢时使用相同模型、窗口、分辨率、音频、缓存状态与素材，打乱测试顺序，记录 CPU/GPU/内存与并发任务。分别比较首声延迟、连续播放欠载、帧间隔、决策和驱动耗时。后台资源加载和模型观察器若抢算力，即使没有代码等待，也算干扰，须限并发、降优先级或延期。

语音时机的可接受误差和身体退出时间不能共用一个数：一个是强调是否跟上台词，一个取决于当前姿势、落脚和持物。每项指标写明测点、范围、异常样本和人工观感；未测到的结果留空。

## 19. 停用、回退和交付方式

每阶段提供关闭自主选择的开关。关闭后拒绝新自发意图、退出当前可退出动作、保持可靠姿势，保留原语音功能与必要打断；不是把全身复位到绑定姿势。恢复旧演示同样只能使用现行合法站姿。

不为动作调度迁移或重写已有记忆、历史、日记和真实后台数据。许可资源说明属于源码，个人偏好覆盖和调度运行记录使用独立运行数据路径。场景状态重启后从实际场景恢复，不能将上次保存的“持书=true”当作书已经重新出现在手中。

每批交付包括：本次实际开放的动作和情境、未开放的范围、自动/人工证据、可运行入口、源码版本与资源指纹、已知问题、回退方式。遵循现有共享工作区规则，从接受的 HEAD 新建分支，只提交本方完成文件，发布后核对远端 SHA。计划不是预先宣告后续每一阶段完成。
