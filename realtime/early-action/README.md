# 动作提前准备：实验性三组测试

在项目根目录双击 `Start-Early-Action-Test.bat`。选择连接方式：1 是直连，2 是使用本机已经运行的 HTTP 代理 127.0.0.1:7890。脚本只读取原有语音配置，不修改 Key 或系统代理。页面打开后先点“试听 / 检查音频”，确认能听到短音，再点“一键运行整批测试”。保持页面在前台，不要同时启动另一轮测试或手动暂停。结束或失败时点“下载结果 ZIP”，把 ZIP 交回 Codex 分析。窗口里的回车也可以打包并停止本实验服务。

测试页为 `http://127.0.0.1:18799/early-action/`。原始结果保留在 `outputs/early-action-20261024/`；打包文件为该目录下的 `Aemeath-early-action-results.zip`。不要删除账本或结果来重新获得次数。重复启动沿用同一批次数与失败保护；已发出模型请求的案例不会自动重跑，未知用量会锁住后续调用。

## 实际测试内容

| 组别 | 要求 Qwen 怎样回复 | 本地怎样执行 |
| --- | --- | --- |
| A | 只给语音，不提供动作工具 | 口型随实际播放；作为声音基线 |
| B | 沿用 D 的先语音、后附动作顺序 | 完整工具到达后，按实际播放时间执行 |
| C | 尽早先给两个动作参数，在同一个响应继续说话，不等回执 | 语音到达前可起势；开播后从同一动作继续 |

这是受控台词实验，B 使用 D 的顺序策略，未复制正式完整对话提示或接入正式检索。三组模型、声音、台词与上下文相同；B/C 工具结构相同，仅顺序提示不同。两种场景（招呼、比较方案）各两轮，交错三组，共 12 响应；另外 2 个为打断探针，总上限 **14 响应**。每个案例严格只有一次 response.create，工具回执在 response.done 后才发。只返回工具没有语音会如实记录，不补发续轮。

两个打断探针有不同证据范围：准备阶段看到身体起势且还没开声时，在本地撤销并拒绝后来音频，但让云端自然结束以取得用量；出声阶段在首声后约350ms撤销本地并发送真正的 response.cancel。后一种可能产生未知用量，所以放最后。若准备时机没有出现，报告写“打断时机未出现”，不能算通过。模型很快结束生成时，本地仍可打断，但不把它声称为取消了活跃生成。

## 哪些数字能说明什么

- 首有声包：服务端发出生成请求到收到含非静音采样的音频块；不是首个静音包。
- 首声播放：浏览器收到请求时间事件，到实际 WebAudio 游标经过第一个非静音采样。另存点击测试到首声，含建连。二者均非物理扬声器声学测量。
- 动作/表情提前：首声时间减去实际PMX合成画面首次达到变化阈值的时间；正数为先动，负数为后动。入队、收到工具都不当作画面已动。自动眨眼与口型不计表情提前。
- 打断：音频源数、关嘴时间、身体收势时间、旧指令拒绝。数据包、主动作、准备阶段共享可信response身份，局部时钟不会绕过撤销。
- 性能：CPU驱动、渲染提交和帧间隔分别记录；渲染提交不是GPU完成时间。每组仅4个主样本，不能据此宣称生产P95或稳定性。

## 保持的行为与边界

原动作轨迹、身体幅度、近身肘部、利落挥手和MotionRig均未修改。新增控制器复用原起手段，在声音未到时只推进至准备边界以内；不会提前完整挥一遍。开播后保持当前相位与速度，经过80ms时钟交接继续主动作；语音没有等待动作或工具回执的条件。若命令晚到则按原调度器处理；没有动作、只点头是合法选项，不自动安排托腮思考。音频暂停后媒体动作冻结，取消后使用原回收逻辑。

表情参数仍是本地短暂表现建议、默认强度0.65。本实验没有接入数学情绪权威流，不修改长期情绪、人设、记忆或交付历史。使用现有语音预览的PMX和动作库，未重做衣发绑定、未启用新的原生动作或完整自主调度中心。用户禁用的Stand2不在工具枚举/准备动作中。

连接失败发生在生成请求前时不消耗响应次数。手动再试会把旧失败文件归档到connection-failures，保留证据。整批遇连接/播放故障立即停止。保留原有未知用量即停规则。ZIP只收集本实验白名单：事件、用量、浏览器计时/轨迹、WAV和6个代表视频；不包含凭据、模型、游戏资源、WAI真实记忆或历史。
