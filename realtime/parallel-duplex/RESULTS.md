# P + WAI 完整语音链路实测（实验性，2026-10-24）

本批完成了接线并实际调用云端，但没有完成全部六段验收。不要把“能运行”解读成“动作同步和出声中打断均已通过”。

## 本批环境和特殊性

- 独立 `parallel-duplex-director-20261024` 实验；上限 6 个 WAI 轮次、24 个 Qwen 响应。
- 实际 Qwen Audio 3.1 Realtime 持续监听、转写和自由语音回复，独立 Qwen 意图规划；动作侧没有预写答案或本轮未来台词。
- 实际 WAI 检索、数学状态、已送达上下文、后台处理与历史 ACK，使用隔离的四条合成种子记忆。没有读取正式用户记忆数据库。
- 仅用户问题由本地 TTS 制成 16 kHz 单声道音频，按原速走真实连续输入通道；回复内容不是重配音稿。
- GPU 本地向量模型为 `google/embeddinggemma-2`，768 维。配置中既有后台辅助模型仍运行，本批单独记录了 12 次 `deepseek-flash` 完成事件；它们不是先写好回答再让 Qwen 配音。
- 摄像头、自主心跳、Neo4j 在本隔离实验中关闭；远场麦克风、扬声器回声和物理声学时延没有验收。
- 首声按首个非静音 PCM 样本的 AudioContext 播放时间计算，未将首个含静音音频包冒充开口。

## 真实观测

第一段用户问：“你还记得我在星桥咖啡店最喜欢喝什么吗？”

Qwen 自由回复：“我记得呀，你在星桥咖啡店最喜欢喝的是无糖柠檬水。”实际播完并进入已送达历史。

| 阶段 | 耗时 |
| --- | ---: |
| 最后有声输入 → 云端断句 | 800 ms |
| 断句 → 最终转写 | 253 ms |
| 最终转写 → 本轮接纳 | 7 ms |
| 本轮接纳 → WAI 上下文准备完 | 266 ms |
| 准备完 → 发出语音请求 | 146 ms |
| 发出请求 → 首个有声采样播放 | 1,102 ms |
| **用户说完 → 首声** | **2,574 ms** |

动作模型返回 `none`，比首声早 **457 ms**。这是正确的“不额外做动作”选择，但不能用它证明挥手同步。此轮应用窗口最小化，画面约 1 FPS，身体时序无效，原始记录保留。

第二段用户在一条音频中纠正饮料偏好。录音内部约 460 ms 的停顿被云端当成分句边界：原有短片段保护合并了“我纠正一下，我。”，但接下来的“现在最喜欢的是无糖乌龙茶”被提前接纳；后续语音又触发插话。

- 输入传输连续：每 5 包的确认间隔约 485–515 ms，未发现网络注入的人为长停顿。
- 前台渲染恢复正常：697 帧，P95 10.1 ms，最大间隔 17 ms。
- 动作建议为 `agree`，到达时音频已经因为仍有用户语音而暂停；调度器只暂存候选，随后撤销，没有点头。
- 取消时播放位置仍为 0，已排队约 2.4 秒音频、实际声源为 0。取消调用返回约 0.9 ms，9 ms 后嘴和身体均静止，后续 3.42 秒记录没有复活。
- 这验证的是**出声前取消**，不等于“正在说话、正在挥手时打断”的云端验收。

唯一未知用量来自被取消的第二段语音响应：服务端返回 `status=cancelled`，但 `usage=null`。本地已经收到终止事件，不是没有等够。两次动作规划及四次监听响应均成功报账。

## 记忆、历史和停线结果

本批共使用 8 个 Qwen 响应：4 个监听、2 个语音、2 个动作。其中 7 个用量已知、1 个未知。没有重置旧账本，没有在停线后继续请求云端。

排空后台后：2 条用户历史、1 条完整助手历史；1 个已交付回复、1 个已取消轮次、0 个待确认交付。未出声的“好的，我记住了……”没有写成助手已送达历史。四个种子记忆仍存在；后台队列全部完成。用户已经说出的偏好仍可能被正常记忆，这与伪造助手交付是不同事项。

尚未完成：纠正后的下一轮检索验证、真实自由问候的挥手同步、真实比较回答的解释动作、已经出声时的云端插话，以及按需完整解析转交的实测。不能以离线测试或旧固定台词实验替代这些结论。

## 根据失败补上的保护

在本实验适配层增加本地 PCM 尾部检查：云端 final、有效判定和监听用量都齐备后，还要确认收到的实际音频已经安静至少 650 ms，且没有后续监听分段尚未收齐。检测只看已收到的 PCM，不读录音文件长度，不看未来文本。

已有足够静音的普通轮次不再额外等待；仍在说话或后续分段未完成则继续合并，不提前调用回复。输入断流不能靠墙上时间流逝自动冒充静音。真正的插话暂停和撤销保留。它是保守的声学检查，不能保证所有语义长停顿都判断正确，背景噪声也可能让等待变长。

修复后的专项验收通过：Python 后端 31 项、HTTP/来源保护 2 项、前端协议 13 项、实际 PMX 调度 16 项，共 62 项。另有原 WAI 链路 67 项、原双工前端 29 项、原准备/播放/调度 69 项回归通过。新增覆盖了 460 ms 句内停顿合并、短回复保留、普通已静音句不额外等待、最后剩余额度、断流不假装结束、取消不复活、撤销音频/字幕不污染新轮等情况。

已获得新一批最多 6 轮、24 个 Qwen 响应的授权，并在 **18804** 启动独立补测服务。此时工具端持续返回 `Local browser use is disabled in Work settings`，即使用户确认已启用仍相同；因此尚未执行新批次网页测试。新批次账本保持 0 响应。首批旧账本与所有失败证据不变。

页面新加的本地挥手预览使用人工 `greet` 指令、已保存问候音频和旧数学快照，单独标为 `simulated_plan_cached_audio`。它可用于接线检查，但不能代替本轮自由回复的云端同步成绩。此按钮及后补的页面检查仍需浏览器可用后验收。
