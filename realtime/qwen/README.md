# Qwen 3.1 Audio Realtime 人物联调实验

这是独立于旧工作室的实验入口：用真实 `qwen-audio-3.1-realtime-plus` 返回的流式语音和字幕，驱动现有 PMX 人物的嘴型、八种表情、短动作及 Claude 的自然身体动作。模型音色固定为 `longanqian_v3.1`。

本分支的特点是**语音直接播放，字幕在本地旁路选择表情与动作**。Qwen 不需要先生成动作 JSON，不调用动作工具；音频链路不等待字幕 Worker 或动作完成。嘴型与动作使用同一个实际 PCM 播放游标。真实接入、自然动作和浏览器渲染都保留各自的响应归属，打断先在本地停声、清嘴型、收回动作，再处理远端取消。

**实验性说明：**这不是已验收的生产语音系统。当前嘴型使用 PCM 能量与三个粗频段估计开合、展口和圆口，属于低成本实时表现，**不是 Audio2Face，也不识别精确音素**。字幕与音频包边界只能近似关联，不能据此承诺词级动作对齐。角色物理关闭，旧模型衣物与头发的碰撞限制仍存在。各项实际运行结果与证据边界由本目录的 `VALIDATION.md` 单独记录。

## 启动

从 `F:\AI-Shared\model_test\face` 执行。需要 Python 3.11 或更新版本、项目已有的 Three.js 依赖、本地模型与贴图。Python 依赖装在机器本地环境中：

```powershell
python -m pip install -r realtime/qwen/requirements.txt
python realtime/qwen/server.py --env-file '<机器本地 runtime.env 路径>'
```

可用 `--max-responses 2` 将一个明确启动的复测批次限制为最多两条回复；它只能降低默认的 12 条上限。该参数不会结算、清除或解释其他批次的未知用量，未知记录需要保留。服务不会自动重开批次。

也可以预先在当前进程环境配置 `DASHSCOPE_API_KEY`，然后省略 `--env-file`。命令中的路径是占位符，不应复制任何人的私有配置到仓库。

打开 [本机 Qwen 联调页](http://127.0.0.1:18769/qwen/)。服务只监听 `127.0.0.1`，默认端口 `18769`，可用 `--port` 调整。启动和加载页面不会自动连接云端；点击“连接 Qwen”后建立会话，发送文字或输入音频后才请求生成。页面通过同源 `/api/qwen` WebSocket 使用本地桥，服务端持有 API Key，浏览器不会取得它。

服务端仅从环境或指定配置文件读取这三个允许的变量；环境值优先：

| 变量 | 用途 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 必需的服务端鉴权凭据 |
| `DASHSCOPE_WORKSPACE_ID` | 可选业务空间；用于生成北京地域 WebSocket 地址 |
| `QWEN_AUDIO_REALTIME_BASE_URL` | 可选自定义百炼 `wss` 地址，路径必须为 `/api-ws/v1/realtime` |

未指定业务空间和地址时使用 `wss://dashscope.aliyuncs.com/api-ws/v1/realtime`。模型和音色由服务端固定，不能通过浏览器任意选择外部 URL、工具或凭据。[百炼模型页](https://help.aliyun.com/zh/model-studio/qwen-audio-3-1-realtime-plus)

## 页面用法

1. 选择输入方式，点击“连接 Qwen”。可以先通过“发送文字，听语音回复”确认真实音频、字幕、嘴型和渲染链路。
2. “发送测试语音”会按真实时间分片发送本机合成的语音。它用于可重复的语音输入测试，不代替真人麦克风验收。
3. “开启麦克风”会请求浏览器授权，并实时把采集到的音频发送给阿里云。点击“结束并提交”、打断按钮或断开后释放麦克风。可使用耳机减少扬声器回声对插话判断的影响。
4. 在回复期间点“立即打断”，观察音频停止、口型闭合及动作从当前姿态收回。“说话时立即在本机打断”使用本地音量检测，阈值判定不能等同语义理解。
5. “字幕驱动表情与动作”与“表现”控制本地旁路。半身、面部、侧面视角可检查真实模型表现。“导出当前记录”保存浏览器本轮计时与调度快照。

两种输入方式需要在连接前选择，切换时先断开：

| 模式 | 行为 |
| --- | --- |
| 手动提交 | `turn_detection=null`。录音结束后提交音频并发送 `response.create`；文本输入也由本地明确请求一次回复。 |
| 服务端自动断句 | `server_vad`，静音判定为 1000 ms，由服务端常量 `VAD_SILENCE_MS` 统一发送与校验。持续音频由服务端检测语音起止并触发回复；不是 `smart_turn` 语义轮次模式。 |

`server_vad` 按声音和静音划分轮次，对句中停顿敏感。一句话中的长停顿仍可能提前触发回复，后续声音又可能取消该回复；把静音阈值延长到 1000 ms 不能保证理解完整句意，也会增加自动断句的等待。需要确定何时提交一句话、比较可重复的延迟或使用停顿较多的测试语音时，手动提交的轮次控制最确定。离线回归验证参数发送与回显验收，不模拟云端检测器、不把本地测试视为真实断句效果。

输入转换为 **16 kHz、16-bit、单声道 PCM**，普通网络分片为 100 ms。输出直接消费 **24 kHz、16-bit、单声道 PCM**；输出字幕来自 `response.audio_transcript.delta`，与输入 ASR 的 `text` / `stash` 字段分别处理。[官方实时语音指南](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-user-guides)

## 实验限额与取消

| 范围 | 默认上限 |
| --- | --- |
| 同时连接的浏览器 | 1 个 |
| 一个连接的生成请求 | 6 次 |
| 一个服务进程累计生成请求 | 12 次 |
| 一个连接的输入音频 | 60 秒 |
| 一个连接的输出音频，包括取消尾包 | 60 秒 |
| 一个连接的存活时间 | 180 秒 |
| 一次响应等待时间 | 45 秒 |
| 云端建连与配置等待 | 20 秒 |

本实验没有把未确认支持的输出 Token 参数发送给服务端。简短回复指令与上述时长、请求数限制共同限制运行范围，但不等同精确费用上限，也不是实际账单。

取消立即撤销当前本地响应。迟到的 `response.created`、PCM、字幕与 Worker 结果不能恢复旧轮。服务端 `response.done` 表示生成结束，尚未播放完的 PCM 仍继续按本地播放游标处理；它不表示扬声器已经播完。

`response.done` 缺失或报告异常 usage、取消后 usage 未知、输出归属冲突、清理失败等情况会关闭连接并阻止该服务进程继续云调用。取消响应可能没有 usage，不能计成零费用。需要先检查证据和未结算状态，再明确开始新的实验批次；本页没有自动重连或隐藏重试。[服务端事件与 usage](https://help.aliyun.com/zh/model-studio/qwen-audio-realtime-server-events)

## 计时与证据

浏览器在同一个单调时钟上记录输入、首 PCM、首字幕、WebAudio 开始播放、实际模型嘴型/表情/骨骼变化，以及本地打断和远端取消回执。服务端 `serverAtMs` 属于另一条相对时钟，不能直接与浏览器时间戳相减。

“输入结束”在音频测试中以最后一个超过能量阈值的输入包为参考，受输入分片大小和检测阈值影响。文字输入则从本地提交开始。WebAudio、渲染权重和骨骼测量不包含未经测量的麦克风硬件、扬声器物理出声、显示器扫描延迟；没有声学回环证据时，不报告物理声学端到端延迟。

服务端仅保存事件类型、时序、归属、帧数及 usage，默认目录为 `outputs/qwen-live-avatar-20261015/server/`，由仓库既有忽略规则排除。使用 `--log-dir` 可指定机器本地证据目录。服务端日志不写入原始音频、字幕、Key 或私有配置路径。浏览器手动导出的快照含测试字幕和输入转写，应作为会话记录对待。

离线桥测试使用 fake provider，不加载真实配置或调用云端：

```powershell
python -m unittest discover -s realtime/tests -p test_qwen_bridge.py
```

节点级口型、实时会话与客户端测试、真实云调用、浏览器渲染和声学测量的结果需要分别记录，不能互相替代。
