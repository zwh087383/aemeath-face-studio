# Qwen 真实流式人物联调验收记录

日期：2026-10-15（用户所在时区）。这版已验证真实 Qwen 流式音频、字幕旁路、PMX 口型/表情/动作，以及 WebAudio 正在播放时的本地停止、收口、收势和远端取消。实验分两批执行，共 7 次响应：5 次完整结束，2 次取消且用量未知；它是有明确边界的实验验收，不代表长期无缝双工或真人麦克风到扬声器的声学验收。

**初批完成 4 次真实 Qwen 回复**，均收到流式 PCM、字幕、有效 usage，实际 WebAudio 播放结束，真实 PMX 嘴型发生变化。字幕旁路在前两次文字输入中驱动了微笑/高兴与挥手；手动语音输入驱动了解释手势。第 5 次使用 500 ms `server_vad` 的多语句语音测试提前断句，随后被继续输入的声音取消；没有产生 PCM，usage 缺失。服务按规则停止后续云调用。用户随后明确批准保留这条未知记录、独立追加最多 2 次回复：第 6 次以 1000 ms VAD 完成连续单句语音回复并显示高兴表情；第 7 次在真实 PCM 正在播放时成功打断，但取消响应仍未返回 usage，因此再次停止云调用。

## 范围与计时口径

模型为 `qwen-audio-3.1-realtime-plus`，音色为 `longanqian_v3.1`。前四轮共用一个手动提交连接，保留其累积上下文；第五轮另建 VAD 连接；第二批的第六、七轮也各自使用新连接，进程最多允许 2 次响应。输入语音是本机合成 WAV，按 100 ms、16 kHz、16-bit、单声道分片发送；它是真实语音输入 API 测试，但没有采集真人麦克风。输出为 24 kHz PCM。

时间均来自同一个浏览器单调时钟。文字输入以提交时刻为基准；语音输入以最后一个 RMS 超过阈值的 100 ms 输入包发送时刻 `inputLastSpeechAt` 为基准，有分包和阈值量化误差，不等于声学最后音素时刻。手动语音另列提交 `commit` 的口径。服务端相对时间只用于核对事件顺序，没有与浏览器绝对时间直接相减。

“首播放”是浏览器 RAF 首次观察到 WebAudio 音源已进入播放区间；“首口型”要求实际模型嘴部权重总和超过 0.04；“表情/手势可见”是渲染循环中实际权重或骨骼变化超过观察阈值。以上包含 RAF 采样误差，不是扬声器出声或显示器光学测量。浏览器报告的 `baseLatency=10 ms`、`outputLatency=40 ms` 是 API 信息，没有据此声称已测出物理声学延迟。

字幕通常早于首 PCM 到达，旁路按实际音频播放位置安排 cue，故“字幕到可见动作”包含等到语音播放及自然动作起势的时间，不能当成纯规则计算耗时。首 PCM 到首口型也受音频起始静音、能量阈值、平滑和 RAF 采样影响，不能当成单纯计算延迟。当前嘴型为 PCM 能量/粗频段驱动，不是 Audio2Face 或音素级口型验收。

02 与 04 使用相同的测试朗读句，分别开/关字幕旁路；但两者处于不同累积上下文，输入 token 为 146 / 331，生成音频分别为 3.76 / 4.24 秒，且只有一对样本。不能从其 904.2 / 754.3 ms 首播放差值判断旁路增加了多少延迟，也不能得出“零开销”或统计显著结论。源码保持音频链路不等待 Worker；性能因果比较仍需受控、重复试验。

## 保留的 VAD 失败与打断边界

05 使用的真实会话回显是 `server_vad`、500 ms 静音。`greeting.wav` 中“你好”后的停顿被当成一轮结束，输入 ASR 当时只确认了“你好”。服务端时间线显示：

| 服务端连接相对时刻 | 事件 |
| --- | --- |
| 1031 ms | 第一次 `speech_started` |
| 1797 ms | `speech_stopped`，随后 `response.created` |
| 2016 ms | 后续声音触发第二次 `speech_started`；原回复 `response.done`，状态 cancelled，usage 缺失 |
| 2016–2031 ms | `usage_unknown_admission_blocked`，关闭连接 |

这轮已产生字幕，但 **PCM 帧数为 0、播放时间为 0、嘴部开度为 0、没有进行中的语义手势**。浏览器曾记录约 22.1 ms 后再次观察到闭嘴，不能据此称为“发声中打断 22.1 ms”；这是本来就没有出声的取消。快照中的 `首字幕相对最后有声包=-147.6 ms` 正是提前回复、输入继续的表现，不是有效负延迟。切换连接时对已结束回复的本地清理记录也不算一次出声打断验收。

服务保留这次未知 usage，停止自动新增云调用。四次完成响应报告的用量合计为 **1240 tokens（850 输入、390 输出）**，输出音频累计 **24.64 秒**；取消响应的消耗未知，不能补成零，实际账单未核对。本节只统计初批次，后续获授权的独立批次另行追加。

## 第二批：单句 VAD 与播放中打断

第二批在保留 05 的未知用量记录后获单独授权，进程使用 `--max-responses 2`。06 的服务端会话确认 `server_vad` 静音阈值为 1000 ms，输入是 6.975 秒的 `continuous.wav`，按实时节奏分包。最后有声包到首播放为 **1233.8 ms**，首 PCM 到首播放为 **59.4 ms**，回复输出 9.2 秒并完整播放；字幕中的“太棒了”触发了实际高兴表情。输入文件末尾的静音仍在发送时已开始回复，因此计时基准是最后有声包，不是整个文件发完。这个结果验证了连续单句路径，**没有复测原 `greeting.wav` 多语句素材在 1000 ms 下是否仍会提前断句**。

07 先请求长文字回复。取消前的真实浏览器快照显示 WebAudio `sourceActive=true`、挥手处于 `prepare` 起势阶段；取消时实际嘴部开度为 0.7055。测试把本机合成的 `interrupt.wav` 剪去 340 ms 前置静音后按实时节奏送入；首个达到 RMS 阈值的 100 ms 包触发本地打断。该轮采用 manual 模式的本地声音检测加远端 `response.cancel`，不是服务端 VAD 自动判定新的自然对话轮次。

| 播放中取消的观察项 | 实测 |
| --- | ---: |
| 本地取消调用返回 | **0.8 ms** |
| 同步返回后的音源 / 队列 | **0 / 0** |
| 实际嘴部回到闭合阈值 | **69.4 ms** |
| 实际身体完成自然收势 | **811.8 ms** |
| 本地桥接确认已发远端取消 | 11.4 ms |
| 收到远端 `response.done`，状态 cancelled | 53.7 ms |

本地收口/收势以本地取消记录点计时；远端两项以发起取消时刻 `cancelAt` 计时。11.4 ms 是桥接确认，不是云端完成确认；53.7 ms 才对应收到云端 cancelled。`remoteCancelNeeded=true`，证明取消发生时远端回复尚需撤销。浏览器取消前已接纳 2.0 秒 PCM，桥接总共收到 2.4 秒 PCM（包括后续尾包）；这不是已播放时长，尾包没有使本地音源或旧动作重新启动。

07 的取消响应缺失 usage。两批共 **5 次 completed、2 次 cancelled/unknown**；已报告的完成响应用量合计 **1536 tokens（1005 输入、531 输出）**，完整响应的音频累计 **33.84 秒**。两条取消的消耗均保留为未知，不能按零计费；没有核对实际账单。第二批已用完 2 次响应额度，且未知用量保护已阻断继续生成。

## 源码修订与未完成项

本批先出现一次握手配置校验失败，未发送音频或请求生成。一次获授权的纯握手诊断确认服务把输入格式回显为 `pcm16`，修复为接受已见证的方向性 `pcm/pcm16` 输入、`pcm/pcm24` 输出别名，仍严格验证模型、音色及显式采样率/通道；随后上述四次完整回复通过。

VAD 失败之后，源码默认改为 `VAD_SILENCE_MS=1000`，发送与回显验证统一；第 06 轮已在云端确认此设置并通过连续单句测试。1000 ms 仍属于非语义静音断句，对长停顿敏感，不能保证完整句意结束，也会增加断句等待。要确定轮次边界，当前应使用手动提交。

补充的 `continuous.wav` 为 16 kHz、单声道 PCM16。词典补充“太棒了/太棒啦”及对应否定过滤的两条回归；第 06 轮真实字幕中的“太棒了”已驱动高兴表情，“太棒啦”变体仍只有离线回归，没有新的同词云端渲染样本。这些修订不能覆盖或删除 05 的原失败证据。

目前没有完成真人麦克风实测、扬声器声学回环测量、VAD 多轮自然对话、原多语句素材在 1000 ms 下的重测，以及精确音素/词级口型动作同步。第 07 轮验证了实际 WebAudio 播放中的取消，但触发输入来自合成语音，不应称为真人声学全链路打断。没有用旧样例 WAV、旧离线打断数字或 fake provider 结果替代未测项目。
