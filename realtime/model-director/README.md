# 模型决定动作 · 实验性接入

本版接通的是对话中的完整动作命令链路：独立动作 Qwen → 完整 function call → 队列 → 已有身体/头部播放器 → 实际执行回执 → 暂停、恢复与撤销。语音、WAI 记忆纠正和播放确认历史沿用 P 方案。动作模型看不到本轮未来回复台词。

动作模型现在能使用现有交流播放器的全部 **73 个公开动作**，每轮没有动作次数上限，可以重复、追加、替换或者清空。这里的 73 个是现有交流动作目录，不是此前导出的 73 段原生游戏素材。原生坐姿、持物、行走和生活活动的场景执行器仍是独立模块；本次没有假称它们全部接入。用户此前禁止的 Stand2 和攻击动作没有重新开放。

## 打开与操作

双击本目录的 `Start-ModelDirector.bat`，默认启动 `http://127.0.0.1:18805/model-director/`。默认不加载云端凭据、不启动 WAI 后台、不创建模型连接，只用本机已有模型、缓存问候音频和人工演示命令。

- **运行本地队列 Demo**：人工安排六个动作，包括两次挥手，检查连续执行。它不是 Qwen 新生成的动作。
- **免费回放所选回复**：已复制本次真实 Qwen 的成功记录时，按原始事件时间重播模型实际选择的动作和实际语音，不再调用模型、不写真实历史。
- **查看 / 修改人工演示命令**：可以在本地 Demo 中追加新指令；`replace` 换掉当前组，`clear` 清空。这个手动入口不能偷偷插入真实云端测量。
- **暂停动作 / 语音、立即打断、只清动作**：分别检查暂停恢复、整轮撤销、视觉失败/撤销与声音解耦。
- **开始录制画面**：录制浏览器画面和 WebAudio 输出，结束后下载。不是外部麦克风或扬声器实测。

本地启动依赖本机既有的私有 PMX、贴图、缓存 `outputs/parallel-duplex-retest-20261024/preview-greet.wav` 与数学状态快照。这些不在 GitHub 源码中；缺失时启动器明确报错，不下载、不伪造。

真实双工使用同一页面与 `ParallelDuplexClient` 的继承实现，接线入口是 `Start-ModelDirector.ps1 -EnableCloud`。需要独立空运行目录，默认上限 3 轮 / 12 个响应，监听转写、语音、动作及转交都计入；后台 WAI 解析另记。不能通过换端口、刷新页面或重复运行来清空账本。未知用量仍然停止后续调用。

## 本地规则现在到底是什么

| 谁决定什么 | 依据与执行方式 | 判断不出来或执行失败时 |
| --- | --- | --- |
| Qwen 决定做不做、做哪些、多少个、如何排序 | 当前用户话语、已送达上下文、检索摘要、只读数学状态、73 个真实可执行动作的名称与时长 | 可以发空数组；本地不会补一个思考、点头或解释动作 |
| Qwen 决定追加、替换或停止动作 | 每条命令的 `operation` | 非法操作整条拒绝，显示具体原因，声音继续 |
| 程序确认指令是否还属于眼前这轮 | 对话连接、轮次、语音响应与 epoch、动作响应、完整参数、数学状态版本 | 旧轮、重复包、过期的状态版本不执行；这不是对台词含义的判断 |
| 程序检查能不能实际播放 | 动作在目录中；当前场景为站姿、空手、无持物活动；真实骨架具有足部支撑 | 未知场景显示等待，不凭空编一个站起或放书动作；用户插话或模型清空可以终止等待 |
| 程序避免同时争用身体 | 一条身体执行通道；等上一条实际实例结束、身体收势通道释放，再开始下一条 | 排队，不因“身体忙”丢掉模型动作，不设额外冷却 |
| 程序遵守模型的开始条件 | `prepare` 允许提前起势，首个实际有声样本播放时释放同一动作；`voice` 等待出声；`delay_ms` 是从命令接收到起的最早延迟 | 没有语音时等待；自然无声结束会释放视觉队列；取消则撤销。不再因 2.5/3.5 秒到期偷偷丢弃 |
| 原播放器决定怎样运动 | 原有曲线、IK、回收过程和速度；当前与旧版同样使用 0.65 强度、速度 1、整体强度 1 | 播放器拒绝会显示失败，不能冒称已展示，也不能停止语音 |
| 原 WAI 数学模型与音频驱动决定表情和嘴型 | 数学情绪快照与实际播放 PCM | 本轮不改表现层，不让动作 Qwen 重写长期情绪、骨骼或口型 |

已移除旧版的关键词准入、首句字幕态度确认、每轮一次、跨轮冷却、低精力禁止完整动作、短语义过期。引用、否定、动作是否得体由动作模型理解。模型可能选得不合适，这版不会再用另一套本地语义规则推翻它。

“每轮无限制”指没有人为动作次数限制，不表示无限内存或无限云调用。单个工具参数包仍限 65,536 个字符，云端生成仍受本批响应预算、服务端 token/时长和连接超时限制。一条工具调用可含多项动作，一个模型响应也可含多次工具调用；超过包长度应分开发送，不按次数截断。界面只显示最近 300 条记录、最后 20 行，已接收的执行队列不因此截断。

## 关键实现边界

`backend.py` 复用原 P 后端的连续输入、记忆有效性检查、异步语音请求、计费结算、取消和历史 ACK，只替换动作模型提示词/工具定义及命令解析。`parallel-duplex/backend.py` 提供可覆写的协议钩子，旧模式默认行为不变。模型动作参数完成就转发，工具回执在模型响应结束后发送，语音连接完全独立。

`director.mjs` 管理模型命令、排队、实际开始/结束反馈与撤销。它直接调用已有控制器的受身份保护执行路径，不进入旧 `RealtimeScheduler` 的“忙或冷却就丢弃”语义队列；原调度器继续管理音频、播放 epoch 与整体取消。两套职责明确，副作用不会通过旧队列再次筛选。

`driver.mjs` 只调整等待、自然结束、暂停的时钟和生命周期，没有改动作定义、求解器、身体幅度、近身肘部和利落挥手。自然结束后剩余动作走现有墙钟尾段；用户再次开口可以暂停和撤销尾段，已完整送达的历史不会被误撤回。

本版动作模型仍在回复前拿一次冻结上下文，一个响应可以提供多条命令；尚未持续读取每一句实际流式字幕再重规划。完整闲时生活/主动搭话中枢、跨坐姿与持物活动执行、视觉观感改善，都不是这次完成范围。
