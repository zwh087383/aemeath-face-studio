# 模型全权动作调度：2026-10-25 验收

这是实验分支。没有修改现有动作轨迹、身体幅度、近身肘部、利落挥手、模型文件、头发或裙摆绑定。语音仍使用原 P 链路，WAI 记忆纠正和播放后历史确认没有迁移到动作系统。

## 已证明的结果

- 接通 73 个现有交流播放器的公开身体/头部动作，不再只开放旧版的五个候选。
- 一轮里没有次数限制；同一个动作可以重复。一条工具调用可包含多项动作，一个响应也可包含多次工具调用，完整指令立即入队，语音不等工具回执。
- 实际浏览器本地演示收到六条动作，起势六条、完成六条、拒绝零。语音自然结束后，队列继续完成；不延后语音播放确认。
- 真 Qwen 在第一轮自主选择 `warm_welcome` 和 `recall_up`，不是预写的动作答案。实际页面两项都执行完成。
- 98 项 JS 检查与 57 项 Python 检查通过，其中本次新增 26 项。涵盖 73 项真实控制器/骨骼离线执行、4,100 条连续追加、重复挥手、播放中及自然结束后的暂停、替换、取消、过期轮次隔离、多工具调用、缺失用量停线、已撤销记忆拒绝、已送达历史保护。

73 项逐项检查使用实际模型检查数据和原控制器，确保能执行、完成及骨骼数值有限；不等于已经人工观看全部动作组合，也不等于所有游戏素材已接入。

## 有界真实云端测试

用户授权最多 3 轮 / 12 个 Qwen 响应。实际停止于 **2 轮 / 8 个响应，其中 2 个用量未知**；没有自动重开批次、没有发送第三条题目。旧批次的账本未改动。

第一轮通过连续 16 kHz PCM 输入真实问题，由云端断句与转写进入实际 WAI，检索隔离环境中的合成记忆，Qwen 自由回答。独立动作 Qwen 只拿当前问题、有限已送达上下文、检索摘要和数学状态，没有本轮未来回答全文。

问题为回家问候并询问星桥咖啡店最喜欢的饮料，模型正确回答“无糖柠檬水”。模型动作 `warm_welcome → recall_up` 均播放完成。该轮已在真实 WebAudio 播放结束后确认写入历史。

第二条本来包含“我纠正一下，现在最喜欢的是无糖乌龙茶……”及较长比较请求。云端把开头切为独立的“我纠正一下”，本地在后续语音到来之前接纳了这一段并开始回答。后续语音被识别成插话，旧轮撤销，语音与动作响应均返回 cancelled 且没有用量，触发既有未知即停保护。原始记录保留。

因此，本次没有完成纠正后追问，也没有完成计划中的“较长回答已经出声且身体正在运动时插话”的真实云端验收。第二轮取消时还没有实际播放音源，不能拿它的 1.3 ms 本地取消返回时间当作真实出声打断成绩。历史最终为两个用户输入、一个完整助手回复，未将被撤销的助手半句写成已送达回复。

最终后台证据还有一项输入维护失败记录，保留在 `final-evidence.json`，没有重试或改成成功。本次不据此宣称记忆纠正已经完成。

## 还没完成的部分

本次解决的是模型决定与动作执行之间的接线和过度筛选。没有解决整个语音链路的断句问题，也没有把缺失用量当零费用。当前模型动作决策仍是每轮开始时的一次独立生成，虽然它可发出多个工具调用和多条动作，但尚不是随每句话持续重规划的导演。
