# D 方案完整链路实测 — 2026-10-17

**结论：记忆、上下文、持续输入、语音、人物调度和送达确认已经接线，正常样本可运行；自然对话的同轮动作输出和插话接续尚不稳定。本分支必须保留“实验性”标记。**

## 本次究竟测了什么

- 真正调用 Qwen Audio 3.1 Realtime，回答现场生成，不提供固定回答台词。
- 持续监听会话负责 smart_turn / 最终 ASR；WAI 用实际预处理、EmbeddingGemma 2（本机 CUDA，768 维）、Qdrant、人物状态和历史组装上下文，再由独立回复会话执行 D。
- 记忆是通过真实插入 API 写入隔离数据库的四条合成事实，不读取原个人记忆库。用户问题由本地 Huihui 语音生成，按原速通过浏览器持续 PCM 输入送入。
- 同一个浏览器内的最后有声输入样本 → WebAudio 开播，是下面的全链路口径。服务器阶段只用服务器单调时钟相减，不混用两个机器时钟。它不是物理麦克风 ADC → 扬声器 DAC 的声学测量。
- 本轮关闭自主后台定时器、摄像头和 Neo4j；口型是既有音频特征驱动。真实人声远场、回声、噪声、长时稳定性和日记归档阈值均未验收。

## 成功样本与延迟

以下是修正外侧空白比对、收紧“先说实质回答再附带工具”的 D 提示之后的样本。样本量很小，不报告泛化成功率。

| 场景 | 说完 → 开播 | WAI 准备 | 回复请求 → 开播 | 动作晚于声音 | 表情晚于声音 | 结果 |
|---|---:|---:|---:|---:|---:|---|
| 饮料记忆 | 4144 ms | 1219 ms | 1174 ms | 点头 109 ms | 微笑 189 ms | 正确回答无糖柠檬水，播完并结算 |
| 招呼挥手 | 4257 ms | 1547 ms | 1245 ms | 挥手 34 ms | 开心 111 ms | 播完并结算 |
| 表情草图讲解 | 3955 ms | 1156 ms | 819 ms | 没有原生动作指令 | 没有原生表情指令 | 产生语音，随后被插话撤销 |

前两条成功回复的全链路中位数约 4.20 秒；回复请求之后开播中位数约 1.21 秒。额外耗时主要在语音断句/最终转写与 WAI 准备，不能把之前固定台词对照里的约 1.28 秒直接称为本轮全链路速度。阶段耗时有并发和包含关系，不能把 observer 所有 span 相加。

前两条成功回复的语音和完整工具调用属于同一个 provider response，且都在工具回执之前到达。表情和动作使用相同播放时钟与 owner；模型没有直接控制关节、动作速度或时间戳。动作“入队”与“实际渲染”分别观测，点头走连续头部反应时也以显示记录判断。

## 失败样本完整保留

本批共 7 次 WAI 回复尝试，15 个 Qwen 实时响应，包含失败与监听器响应。

1. 初始一条正确检索并产生语音、微笑和点头，但 Qwen 字幕尾部换行被 WAI 清理，过严的内容比对拒绝了送达。已改为只规范化外侧空白，内容改变仍拒绝，后续真实成功样本完成了 ACK。失败历史没有被补写。
2. 之后两条自然回答只有工具，没有语音。没有通过隐藏第二响应补音，也没有当作成功。它们触发了提示收紧。
3. 收紧后两条短回答正常；长解释只出了语音，没有工具。D 的同轮约定仍是模型行为，不能宣称协议层保证。
4. 插话素材“等一下先别讲步骤了，我的蓝色笔记本一共有几本？”被 smart_turn 切成“等一下，先别讲步骤了。我。”与“蓝色笔记本一共有几本？”。第一段先进入 WAI，第二段又撤销了刚启动的回复。**完整插话接续未通过，也没有拿到问题的最终回答。**

发生取消的回复收到 `response.done(status=cancelled)`，但 `usage=null`。ledger 保留 unknown=1、blocked=true；之后没有再调用云端。原计划最后一条单独远端取消试验没有执行，实际误断句引发的取消作为观察证据记录，不伪装成原计划成功。

## 打断：哪些已证明，哪些没有

- 真实插话先触发本地临时暂停，再在云端有效轮次确认时撤销旧播放。撤销时清掉约 **14.67 秒**剩余音频，调用返回约 **0.5 ms**；声音源保持为 0，约 **12.9 ms**后观察到闭嘴。此时音源已经被临时暂停，所以 0.5 ms 不是“从用户开口到静音”的延迟。
- 被插话的长回答没有原生动作指令，不能把这次真实插话算作正在挥手时的手臂收势证据。
- 后一个回复的远端取消发送到 `cancelled` 终态约 **94 ms**，用量未知依然停止；这个回复尚未实际开播。
- 补做保存真实挥手事件的本地回放打断：在挥手/声音进行中按下打断，4 个音源 → 0，本地返回约 **0.6 ms**，约 **14.1 ms**闭嘴，约 **820.7 ms**收势。它是**离线回放的本地打断**，没有新的云端请求，不能代替远端双工接续验收。
- 连续两次回放都正常播完，原生 call_id 相同、本地 epoch 执行 ID 不同；回放不写入 WAI 已送达历史。

## 实际持久化与额外调用

最终连续会话的持久化核查：4 条已接受用户输入，2 条完整助手回复；2 个 delivered、1 个 cancelled 交付，active ACK=0。日记缓冲 6 条，small/daily/weekly 归档均为 0。输入维护 12 项 done、回复效果 5 项 done，最终 quiescent=true、successful_drain=true。未播完的长回答和被取消的下一条没有变成完整助手历史。

上下文消息数随连续会话从 2 → 4 → 6 → 7 增长；后续上下文包含已播完的回复，未将取消回复认定为已说完。检索证据和实际提示中确认含合成事实。

实时已知用量小计 **21375 tokens**，未知 1 条，不能视为完整费用。此外，WAI 原有模型客户端记录了 **38 次 deepseek-flash 辅助请求**（三个运行实例分别 5/10/23），不包含在实时响应 token 小计里。最终实例的处境模型有 4 次结构化输出字段校验失败并使用既有降级路径；传输层 completed 不能证明语义解析成功。

## 测试后补丁与证据边界

新增窄范围悬句保护：只对被标点隔开的孤立尾词（例如“我。”）最多等待 1.2 秒；下一段到来时保留两段原始转写并一次交给 WAI。普通完整句没有额外等待，不靠重写 ASR 补词。

用本次观察到的两段文本做了确定性回归，验证只产生一个 WAI admission；同时验证“我喜欢你。”不被误延迟，孤立片段没有后续时有界放行。**该补丁只有离线证据，因未知用量规则尚未再次调用云端验证。** 不把之前失败的插话录像写成补丁后成功录像。
