# 2026-10-17 记忆快答与连接预热：真实三组实验

## 结论与证据边界

快答通道已实际接通，但没有测得端到端收益。连接预热确实缩短了上下文就绪后的请求准备；快答模型约 0.9–1.0 秒的非流式 JSON 决策，加上随后的 Qwen 语音生成，抵消了不等待其他解析的收益。

这是 10 次 WAI 尝试、21 次 Qwen 响应的受控小样本。三组各用全新的隔离 WAI 数据、相同四条合成事实、相同本地合成用户问题；模型回复为真实云端现场生成。不是物理麦克风到扬声器声学测量，也没有使用原私人记忆库。摄像头、Neo4j、自主定时器关闭；日记未达到归档阈值。快答通道只通过受信任 Python 回调开启，原全局 `memory_first_reply` 开关仍为关闭，不能根据 bootstrap 收据中的该字段判断本次快答是否执行；逐轮 `fast_reply` 和 `route` 是实际证据。

## 同题短答

只对三组最终 ASR 完全相同的两道短题比较；长句最终转写不一致，不能把它较短的等待作为优化收益。下表单位为秒，从用户最后有声样本到 WebAudio 开播。

| 问题 | 完整前置 / 原连接 | 完整前置 / 预热 | 记忆快答 / 预热 |
| --- | ---: | ---: | ---: |
| 还记得我在星桥咖啡店最喜欢喝什么吗 | 3.096 | 3.316 | 3.738 |
| 早上好呀，今天见到你很开心 | 3.635 | 3.551 | 3.622 |
| 中位数（各 2 条） | 3.365 | 3.433 | 3.680 |
| WAI 准备中位数，含快答模型 | 1.469 | 1.477 | 1.516 |
| 上下文就绪→生成请求中位数 | 0.195 | 0.087 | 0.155 |
| 生成请求→首 PCM 中位数 | 0.574 | 0.545 | 0.765 |

云端时变和回答长度不同，无法据此断言快答一定慢多少，更不能把三条混合成功样本的中位数包装成同题改善。WAI 准备为服务器计时，其余为浏览器同一时钟；不要把跨钟字段不加区别相加。没有模型内部 prefill 单独计时。

## 路由、记忆、表情和动作

- 记忆题和社交题各一次真实 `§DONE§`，程序采纳；快答决策分别 984、890 毫秒。Qwen 实际转写与获准短答一致，完整播完后确认送达。
- 记忆题准确命中合成的“无糖柠檬水”。快答 `usedMemoryIds` 为 `81001`；后续社交题的检索已包含本次对话固化的新记忆。当前实现使用最近 10 条对话、top-3 本地语义记忆、人设和现有治理约束。
- 挥手题模型返回 `§DONE§`，但程序没有采纳，转完整路径；不得把它算成快答成功。Qwen 随后真实输出 `happy + wave`，播放和动作均完成。
- 长解释题实际返回 `§HANDOFF§` / `long_answer`，转完整路径并复用正在运行的解析；没有重复发起一次新的整套解析。随后因长句被切分发生取消，未完成语音播放。
- 快答记忆 / 社交 / 转交后的挥手，动作晚于声音约 372 / 419 / 595 毫秒，表情约 303 / 419 / 516 毫秒。对应音频和工具调用为同一个 responseId，均早于工具回执，未等回执再出声。
- 全部 9 条完整送达回复中，6 条实际有表情和动作，3 条只有语音。原连接组社交和长解释、预热组长解释缺少动作。D 提示约定不保证每轮模型都调用工具，也不保证逐词语义同步。
- Qwen 快答输入仅 713 / 715 个文本 token，完整记忆回复约 3150；这是 Qwen 一侧输入减少，不能据此断言整条链路更便宜，DeepSeek 快答和原后台辅助仍有费用。

## 打断和未完成项

云端 `smart_turn` 把快答组长句在“绘制步骤”处切开，把后续“大概……”当成新轮次。第一段已发起 Qwen 回复，第二段有效轮次将其取消。取消终态 `usage=null`，账本立即记录 `unknown=1` 并阻止新请求。原有只识别孤立悬句的 1.2 秒保护未覆盖此分段。

该轮尚未开始可观察的播放，现场中断记录 `sourcesBefore=0`、`activeMotion=false`。**这不是出声中插话通过。** 自动脚本尚未发送计划中的 barge 素材就已停止；后续自由追问和独立远端取消探针没有再执行。

离线使用本批保存的真实挥手语音与原生工具事件，连续完整回放两次后于第三次挥手中撤销：5 个音源清零，撤销返回 1.5 毫秒，18.2 毫秒收口，819.5 毫秒收势。新录制的可观看打断演示为 11 音源清零、0.5 毫秒返回、16.0 毫秒收口、826.2 毫秒收势。两者均验证零新增云端响应；回放不产生送达 ACK 或新历史。

另有预热组会话在约三分钟空闲后报告 `provider_error`，没有缺失的响应或未知用量。一次输入在本地以 `input_not_ready` 拒绝，零云端请求；确认原会话清理和预留释放后，手动重连继续同一账本与原历史。该失败仍保留，不能称长时保活已解决。
