# 完整角色混合测试（实验性，2026-10-27）

本批按用户明确授权执行100个对话场景：80个一问一答，10个短间隔五轮对话，10个长间隔五轮对话，共180轮。用户随后明确要求模拟时间流逝；长间隔逻辑时间大于60秒且小于300秒，以最多10倍速推进闲置排期和原数学情绪的idle_update。模型、声音、口型、动作及真实来源/记忆时间保持原速，不修改系统时钟。10个长对话场景内交叉20项真实WAI阅读业务：10项正常完成、5项被用户叫住后恢复、5项注入业务失败。

初版真实等待的4个尝试单独保留，随后建立模拟时间批次，不覆盖原账本。初版还暴露了闲置约509秒后的provider_error，以及同端口切换场景时浏览器缓存旧音频清单；前者保留为真实连接生命周期问题，后者以no-store和云连接前清单一致性检查修复。模拟时间测试不冒充真实多分钟连接稳定性/面部语义TTL验收。

情绪按场景计数：高度悲伤10、高度兴奋10、略微悲伤40、较为高兴40。每个场景只在开始时设置一次隔离WAI数学系统的实验初值，随后按真实时间变化。后续是否仍保持原强度以记录为准，不能把初始标签冒充全程实测状态。

## 如何运行与计数

`manifest.py`用固定种子20261027生成可复现清单和次序。清单包含用户话语、情绪初值、间隔和业务故障，没有动作序列或表情目标。动作使用上一批的DeepSeek原格式函数工具和83项目录；语音使用Qwen完整检索、历史和双工链路。动作模型不知道未来完整回答。

每个场景使用独立WAI数据目录、原用量账本实现和原浏览器播放器。多轮场景的五轮使用同一个运行实例与历史；各场之间隔离。每场只自动尝试一次，失败保留，不靠挑选重跑结果提高通过率。

短间隔通常在上一条结束后2～6秒继续；其中5场在声音仍播放时输入下一句，以检验真实语音插话。另有16个单轮和5个长间隔场景，在首声后的固定随机时刻通过原取消入口中断输出；单轮取消不偷偷增加第二个问题。长间隔对话的五次活动插话仍在规定间隔后通过真实用户PCM进入。

后台使用现有真实阅读链路与固定NASA月球页面，保留来源、生成笔记、持久化活动、暂停/恢复和完成事件。业务排期沿用原实验的30倍折算及120秒最短活动，排期时钟在长间隔内加速；真实读取/模型任务仍在计算时，额外时间推进暂缓，不能跳过计算直接编造产物。人物物理动作仍按真实时间完整播放，可能跨越被压缩的业务阶段，结果如实记录。失败分别为拒绝读取、超时、空正文、来源撤回、读取工作异常；它们是明确标记的故障注入，不冒称网站真的发生故障。动作失败与业务失败分别记录，不能用伪造动作完成回执推进模型。

## 用量与中止

所有场景上限相加：监听400、语音300、动作3000、后台1960次响应，总上限5660；输入PCM8400秒。这是防止反馈循环失控的硬回退上限，不是目标用量。每场另有更小限额，未用的场景额度不自动借给别的场景。调度器启动新场景前汇总本批和初版诊断用量，并预留该场各通道的完整上限；超过总上限则不启动。

本次用户已授权独立完整测试及自行处置：已确认终态但usage缺失时保留未知与最大预留，不退款；无法确认终态时冻结对应通道。此前严格未知即停的独立批次完全保留，新测试不修改、清空或恢复其账本。该策略只由本批独立服务选择，普通DeepSeek入口仍保持严格未知即停。

`run.py`按序启动隔离服务和真实浏览器，保存每场输入、模型事件、真实动作回执、数学/脸/身体采样、原速WebM、最终历史与队列、用量和机器负载。重启调度器跳过一切已经尝试的场景，不重复收费；运行状态存在但证据不完整时标记故障。

## 验收应看什么

- 对话是否真的有声音：用户尾音→首声、模型请求→首声、声画开始差异分别计算。
- 模型决定和真实执行分别统计，包括拒绝、依赖阻断、重复动作、动作结束后的自主续接及无动作。
- 长间隔内的任务开始、成果、完成，与角色站坐、持书和收势是否一致；不能只看任务标签。
- 输入插话后音频暂停与确认取消分别计时，检查旧队列是否复活，当前来源是否撤回。
- 情绪采样是否实际达到初值、随后如何变化，眉眼与口型是否冲突。原速录像用于观察；数值通过不等于审美自然。
- 历史只确认真正交付的回答，纠正和撤回保留真实结果；所有未知用量独立列出。

用户声音来自本地Windows Huihui合成PCM，回答与动作来自真实云模型。这里验证浏览器WebAudio和实际渲染链路，不能当作真人麦克风、回声消除或物理扬声器验收。测试器不修改身体轨迹、幅度、近身肘部、挥手速度或面部控制器。

代码冻结与执行结果应结合每场`case-source.json`和最终报告；本文描述测试设计，不预先声明100场通过。
