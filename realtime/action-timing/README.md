# 更早动作指令：独立实验

这轮实验只回答一个问题：Qwen 的动作选择能否在声音开始前完成，同时让语音不等待动作请求或工具回执。它复用现有 PMX、表情配方、动作轨迹和音频播放器，不改变身体幅度、近身肘部、挥手速度、衣发绑定或 WAI 的数学情绪。

这是固定上下文、固定回复台词到真实流式音频和画面的实验，不是正式聊天系统。没有接入麦克风断句、记忆检索和正式历史记录。所有动作都是本轮短暂表现建议，不写入长期情绪状态。游戏资源、PCM、私有运行配置和密钥不随源码发布。

## 怎样比较

每组各用招呼和解释两段相同台词。顺序为招呼 D/N/K/P，再解释 P/K/N/D，减少总是最后测试某组的偏差；两条样本只能说明此次观察，不能证明稳定成功率或性能分位数。

| 组 | 请求方式 | 唯一变化 |
| --- | --- | --- |
| D | 一个语音响应附带工具 | 现有语音优先提示，工具包含表情和动作两个字段 |
| N | 一个语音响应附带工具 | 不规定语音和动作的输出先后，要求在确定时尽早附带动作 |
| K | 一个语音响应附带工具 | 在 N 的基础上，将参数缩为一个短编号：不动、招呼、解释 |
| P | 两个独立 Qwen 会话同时请求 | 一个只回复语音，另一个只选择短动作编号；两者互不等待 |

两段 P 各消费两个模型响应，其余各一个，整个新批次最多 10 个响应。旧 early-action 批次的 14 次额度和已有记录不动。用量未知时停止后续调用；重启不清账、不自动重试已发送的样本。已同时发出的两条 P 请求会继续接收结束和用量，不因为其中一条出错就丢失另一条账目。

K 同时缩小了候选范围，因此它和 N 的差异不能全部归因于 JSON 更短。D/N 也可能选中与 K/P 不同的表情或动作；报告须列出实际选择，主要依据命令到达与首声时间判断协议效果，不能把不同动作本体的起手时长当成协议收益。

为公平比较生成任务，所有组使用相同已给定的回复台词，P 的动作选择请求也能看到这段台词。这对 P 是有利条件：它测试的是已知回复内容时的时序上限，不能证明真实自由对话中独立规划器能提前知道主回复的结论。真实接入时，赞同、否定和强烈情绪等依赖回答立场的表现仍须等待实际回复确认。

## 时间怎样算

连接和会话配置先完成，再发出本轮请求。分别记录点击到首声和请求到首声，不能用提前建连掩盖用户端等待。P 以共同时钟记录两条请求实际发送时间，不将两者假定为绝对同时。

记录首次工具项、首次参数增量、首次严格可解析的完整参数、参数完成、首个有声音频包、浏览器首声、身体和表情首次可见变化。半截 JSON 只用于计时，不执行动作；只有本轮身份正确、完整且校验通过的工具参数才能准备动作。参数完成后才回执，且回执在生成结束之后发送，不创建第二个响应补语音。

首声以第一个有声 PCM 采样在 AudioContext 的调度时刻计算，不以第一包静音、首条字幕或第一次画面刷新代替。它不包含物理扬声器和房间声学测量。身体与表情的可见变化使用同一套真实模型姿态阈值；没有指令或没有变化记为空，不算作零毫秒。

动作早到时，复用原动作的可撤销准备段，首个有声采样开始时再连续进入主动作，不从头重播。声音先到时立即播放，后到动作在仍相关且轮次有效时接入。缺音和显式暂停冻结已释放的动作时间；打断使该轮语音和动作一起失效，迟到事件不能复活它。

## 怎样判定有效

- 正常出声是前提。只给工具而没有语音，无论工具多早都算本组失败。
- 同时报告完整命令提前量和实际身体/表情提前量。不能把“已选好动作”当成“画面已运动”。
- 不为同步增加语音等待，也不加快原动作轨迹。晚到仍如实记录。
- P 的语音结束独立交付，不等待动作请求结束。并行会增加一次调用，也可能争用网络或服务端资源，是否更快只能看实测。
- 保存原始服务事件、用量账本、机器状态和源码/配置摘要；云端实测与本地重放报告分开，不能用重放冒充新增云端或麦克风测试。
