## 本机性能测量

环境：Windows x64，Node v24.15.0，Headless Chrome 155，32 个逻辑硬件线程，Web Audio 48 kHz。没有加载 PMX 或云端模型。它是这台机器的局部测量，不是设备性能保证。

Node 纯规则微基准使用 16 个固定句子、80 个正式配对批次，每批 320 次，共 **25,600 次规则分类**：

- 批次内每句均值的总体平均约 **0.00985 ms**。
- 上述“批次内每句均值”的批次 p95 约 **0.01233 ms**，不是逐调用时延 p95。
- 单次结果最多两个 cue；不含 Worker 消息、音频提交、渲染或网络。

浏览器先热身一对，再交替进行 **4 对开/关测试，每段 2 秒**。两侧使用相同 20 ms PCM 投递与每 120 ms 一次的相同字幕；固定脚本动作关闭，字幕内容被规则抑制为零动作，避免不同动作量干扰成本比较。

| 指标 | 旁路关闭 | 旁路开启 |
| --- | ---: | ---: |
| PCM append handler p95 的四次均值 | 0.200 ms | 0.200 ms |
| 字幕 push handler p95 的四次均值 | 低于计时分辨率 | 0.100 ms |
| 播放同步/调度每帧 p95 的四次均值 | 0.100 ms | 0.100 ms |
| 首次观察到 Web Audio playing 的四次均值 | 43.75 ms | 38.70 ms |
| 页面帧间隔 p95 的四次均值 | 5.600 ms | 5.075 ms |

这些短样本受浏览器排程和计时分辨率影响，开启后数值更低不表示旁路加速了音频。不同试跑的帧间隔有波动，不能据此承诺零资源竞争或实际角色渲染帧率。本轮没有观察到 PCM 接收处理成本或开始播放因旁路而增加。

打断的同步处理返回时，音频源节点、动作队列、旁路待处理增量均为 0，Worker 无在途任务；旧轮字幕被拒绝。该次处理计时低于浏览器分辨率，记录值为 0，**不能解释为物理停音频耗时为零**。
