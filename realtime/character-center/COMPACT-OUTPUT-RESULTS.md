# 动作输出压缩对照：更快，但极简编号版可靠性未通过

2026-10-27。完成 DeepSeek 原格式/压缩格式各 6 次真实调用。压缩能减少输出与等待，但本批原格式 6/6 次形成合法指令，压缩格式只有 3/6 次；因此保留为实验协议，尚不适合替换实际动作旁路。

## 改成了什么

原格式分别调用 set_expression、perform_actions，输出长字段名、动作 ID、完整依据 ID。新实验只调用 p：

```json
{"f":[0,3,0.6],"a":[[0],[20,1]],"g":"先挥手，再会意点头确认"}
```

以上是本批一条命令的简化展示。f 依次为表情模式、种类、原精度强度、依据索引；单一依据可以省略最后的 0。a 的每项依次为动作编号、开始锚、迟到处理，尾部默认值可省略。编号只在当前请求绑定的完整目录版本中有效，不是永久跨版本约定。

o 保留保持/追加/替换/清空；r 保留完成后再决策、仅失败再决策、等待新事件；g 保留模型自己选择的目标。没有减少 83 项能力，没有限制一轮动作数量，没有把强度量化成几个档位。缺省 review 仍是原来的 on_finish，没有借压缩改成默认等待。

解码器把 p 还原为原来的脸和身体命令，继续使用原字段、动作枚举、模式/表情搭配及依据检查。未知编号、布尔值冒充编号、无效强度、过期目录版本和多余控制字段会被拒绝。当前单个 p 原子校验，脸字段错误也会使同包身体失效；这比原来两个工具的错误隔离更紧，是下一版需要调整的限制。

## 如何对照

使用相同的三份冻结快照：普通饮料提问、阅读开始、已挥手完成后的续选。每份各两次，交错原/压缩顺序。两边用户 JSON 完全相同，原能力目录共同增加 n 编号列及目录版本；原 ID、含义、条件、时长、效果均保留。提示词语义以现有规则为基础，压缩版替换工具写法并补编码说明；工具 schema 必然不同，不称“全部输入 tokens 完全相同”。

使用同一个 deepseek-flash、非思考模式、已有本机代理和复用 HTTP 连接。没有语音、转写、真实动作播放、活动执行或自动续选。没有把完整未来台词交给模型。输出长度与工具定义同时变短，输入中位数也从 4,530 降至 4,161 tokens；不能把所有耗时收益只归于输出。

## 实际结果

| 结果 | 原格式 | 极简编号格式 |
| --- | ---: | ---: |
| 真实响应数 | 6 | 6 |
| 形成完整合法指令的响应 | **6/6** | **3/6** |
| 普通文字冒充工具调用 | 0 | 2 |
| 工具参数被原校验拒绝 | 0 | 1 |
| 全部响应输出 tokens 中位数 | 230.5 | 86.5（含失败，不能单独当成功收益） |

只取压缩版成功的三条，与同场景、同重复序号的原格式逐条配对：

| 有效配对 | 原格式完整合法身体指令 | 压缩版完整合法身体指令 | 原/压缩输出 tokens |
| --- | ---: | ---: | ---: |
| 饮料提问，第 1 次 | 2.067 s | 1.120 s | 320 / 100 |
| 饮料提问，第 2 次 | 1.592 s | 0.834 s | 224 / 84 |
| 挥手完成后，第 2 次 | 1.847 s | 1.205 s | 330 / 93 |

这三组有效配对的中位耗时从 **1.847 s 降至 1.120 s**，约减少 **39.4%**；输出 tokens 中位数从 320 降至 93，约减少 70.9%。这是成功子集的条件统计，不掩盖另外一半压缩响应失败，也不能推广成整体成功性能。计时统一减去 requestSent；使用 finish_reason 确认完整工具参数后再解码，没有执行半截 JSON。

全部六条原格式首份完整工具参数中位 1.645 s；压缩版仅四条真正工具调用，参数中位 1.123 s，其中一条非法。不能把另外两条无工具响应记成零延迟，也不能把四条都称为可用动作。

## 具体失败与选择质量

- 阅读开始的第一次，模型把 p({"o":0}) 写进普通文字。第二次也输出两行 p(...) 文字，且其中包含错误的表情模式和 keep 搭配非空动作。它们均未经过真实工具通道，不会被当作动作执行。
- 挥手完成的第一次，实际调用了 p，但 f=[0,10,0.5,0] 把“短微笑”种类放进了持续态度模式。原校验拒绝，整包没有生效。
- 压缩版成功的三条仍选择挥手，包括已经挥手完成后的案例。压缩没有解决旧请求重做或持续目标结束的问题；目标文字存在，也不等于正确选择后续动作。
- 本批原格式一次自行选择 sit_down、take_book_seated、read_seated 三步，另一次阅读选择 keep/wait。它们只是模型命令，没有实际执行回执，不能算自主完整读书已经通过。

失败说明，固定位置数字数组和同一份协议里残留的自然语言功能名对当前模型仍有歧义。下一版宜保留短字段及动作编号，给表情模式/类型保留明确可区分的枚举，并约束为真实工具通道；需要新的云测才能判断这些改动是否有效。本轮不把普通文字修成工具、不把错误编号宽松转换成“看起来合适”的表情。
