# 有效动作保留：两个真实场景的本地新旧对照

这是 2026-10-28 的实验性修复，针对“同计划里一个动作错过时机，系统重新决定，又把刚开始的有效动作取消”的问题。它改执行反馈和计划替换规则，不改动作轨迹，也不替模型选动作。

本批基于原 face 测试版本的 83 项能力目录，基线是 `21288ee870b178d80c5b38eb060625d9ae1e5589`。独立工作区的 262 项扩展库未合入。

## 现在由谁判断，怎样处理

| 遇到的情况 | 处理者及依据 | 实际行为 |
| --- | --- | --- |
| 一个动作过期或失败，但同计划还有有效步骤 | 执行器上报真实结果，后端核对已下发的指令和步骤 | 先记录这一项，等其余步骤各自完成、失败或撤销；不因这一条反馈立即重做整套计划 |
| 模型收到新信息，发来普通替换 `replace` | 调度器区分尚未开始、已接纳、已开始 | 只替换同一来源尚未开始的动作；已进入执行器的有效动作继续，包括开始前的身体衔接阶段 |
| 模型明确判断当前行为也应停止 | 模型选择已有的 `clear` 指令 | 停止本来源当前动作、清理后续，并使用原执行器的收势流程 |
| 用户插话、来源失效或记忆纠正导致撤销 | 原有轮次/来源保护直接处理 | 无需等模型或等动作完成；撤销当前与后续动作，迟到的旧指令不能重新生效 |
| 整套已选步骤有了真实结果 | 后端汇总所有结果及当前身体状态，按原 `review` 约定通知模型 | 模型决定接着做、换目标、保持或停止；本地不补写动作序列 |
| 只知道指令发出，还没有执行回执 | 后端给模型标为 `issued` | 不冒充已开始或已完成，不用超时伪造完成结果 |

前端现在分别上报“已接纳”“已开始”和终态。进行中的状态只帮助模型了解身体实际情况，不触发又一次模型调用，也不确认对话历史。旧计划的当前动作被保留后，其最终结果仍会记录，但不会另起旧目标的竞争性续接请求。

同一指令里前置步骤失败，尚未开始的依赖步骤仍按既有规则停止。这项修复保护的是仍有效的动作，不会强行执行失去前提的后续动作。普通替换不影响其他来源的计划。

## 实际对照结果

两边输入当时保存的同一批真实 DeepSeek 工具指令，并用真实 PMX 模型、原动作轨迹、1 倍原速运行。旧版故意产生的重复替换，也原样发给新版，以检验它能否保住当前动作。

| 场景 | 旧版执行器 | 新版执行器 |
| --- | --- | --- |
| short-03：安慰动作 | 启动约 63.4 ms 后被普通替换取消 | 保留并执行约 3595.7 ms，直到原记录中的真实插话撤销到来；不是自然完成 |
| short-08：欣喜动作 | 同一动作时钟帧内开始并被取消，记为 0 ms | 完整执行约 3656.8 ms，之后执行后续新选择 |

两场目标动作“已开始却被普通替换取消”均从 1 次变为 0 次。原录像中的 short-03 曾记录约 70 ms；这里的 63.4 ms 来自受控重建，存在少量帧边界差异，不能拿它冒充原录像精确时点。

同一批执行结果另外交给旧、新后端方法做离线反馈验证：

- short-03：旧版在录像时间约 21.4004 秒立即请求重新决定；新版让其余动作继续，之后用户插话使旧轮次失效，因此没有再请求续接。
- short-08：旧版在约 13.4934 秒请求重新决定；新版等有效动作完成，约 18.3969 秒再请求一次，并携带所有步骤结果。

这里捕获的是“何时请求模型决定”，没有让假模型生成续接动作，也没有发起新的云端响应。页面中的旧指令压力回放和后端反馈验证是两个互补检查，不能合称一场新的完整自由对话。

## 打断与保护检查

在新版安慰动作执行中按下“现在插话”，两个本地调度器的当前、排队动作立即撤销，继续推进时间后的旧指令被拒绝。本次本地取消函数约 0.2 ms；这不包含麦克风、断句、云端确认或物理出声，不是端到端打断延迟。

首次打断测试发现对照页漏接正式调度中心已有的整轮撤销保护，使另一来源的迟到旧指令重新进入。保留失败记录后，已在对照页补上同样的轮次保护并复测通过；没有为通过测试放宽正式保护。

- Python：153 项通过，覆盖后端、原接口、DeepSeek、续接和新增动作保留回归。
- Node：54 项通过，包含真实调度中心的语义更新、来源有效性、显式停止、表情动作并行和插话回归。
- 真实模型双场景原速对照已录制，另保存斜侧打断前后截图。
- 14 项保护文件哈希不变：包括原 9 项未完成修改、身体动作控制、动作参数、持续表情和场景模块；身体幅度、近身肘部、利落挥手的轨迹未动。
- 112 份旧账本哈希不变；本批新增云调用为 0。
- 页面和本地数据返回 200；私有账本路径 404、外部 Origin 403、写请求 405；原录像分段读取 206。

脱敏数字见 [RESULTS.json](RESULTS.json)。原始模型、音频、录屏、指令、账本及测试输出保留在本机 `outputs/action-preservation-20261028/`，不随源码发布。

## 在本机查看与复现

从 face 根目录运行，使用已有 Python 环境和 Node：

```powershell
python realtime/action-preservation/build_data.py
node realtime/action-preservation/server.mjs --port 18821
```

打开 `http://127.0.0.1:18821/action-preservation/`。选择 short-03 或 short-08，点“从问题前开始 · 原速”。左旧右新；可切正面、斜侧、侧面，可暂停或按“现在插话”。此按钮注入本地撤销事件，不启用麦克风。上方为无声动作对照，下面折叠区可单独播放当时原始录像与声音。

自动浏览器验收只能使用 `realtime/character-campaign/browser-config.json` 的 headless Chrome，不弹前台：

```powershell
playwright-cli -s=action-preservation open http://127.0.0.1:18821/action-preservation/ --config=realtime/character-campaign/browser-config.json
playwright-cli -s=action-preservation run-code --filename=realtime/action-preservation/check-browser.js --raw > outputs/action-preservation-20261028/browser-comparison.json
python realtime/action-preservation/check-feedback.py
playwright-cli -s=action-preservation run-code --filename=realtime/action-preservation/check-interrupt.js --raw > outputs/action-preservation-20261028/interrupt-browser.json
```

`record-browser.js` 记录当前选中场景的原速左右两段视频；`audit-local.py` 核对本机的测试结果、保护哈希和 HTTP 路由，再生成脱敏结果。它们要求已有原测试证据与对应本地素材，不会自动下载私有模型或调用云服务。

本批未重新测自由对话、首声延迟和真实麦克风插话链路，也未处理先前发现的持续表情、口型冻结或后台活动输入问题。两个场景证明本次动作保留规则有效，不能据此声称整套角色系统的全部问题已解决。
